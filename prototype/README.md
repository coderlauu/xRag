# 交互原型

每个模块一个子目录，一个自包含的 `index.html`（无构建步骤、无外部依赖，双击即可打开）。

| 模块 | 原型 | 对应规格 |
|---|---|---|
| AI 知识库建设 | [knowledge-base/index.html](knowledge-base/index.html) | [tech/knowledge-base/ui-spec.md](../tech/knowledge-base/ui-spec.md) |

## 原型和 ui-spec 的分工

`ui-spec.md` 是**规格**，是唯一权威：字段、状态规则、成品文案以它为准。原型是**用来评审规格的**——一份 400 行的文档，要在里面校对"四种状态的按钮文案对不对""`SKIPPED` 的措辞会不会让人误以为出错"很累，而这些恰恰是看一眼页面就能判断的东西。

两者冲突时以 `ui-spec.md` 为准，并把原型改回来。

## 演示控制台

每个原型底部有一条深色抽屉，可以切换文档状态、空态、触发各种错误提示。它刻意做成"脚手架"观感，**不是产品的一部分**——真实系统里这些状态由后端数据决定。

它存在的唯一理由是让那些"只在特定状态下才出现"的界面规则变得可评审：`RUNNING` 时该灰的按钮、父文档禁用时"批量启用"灰而"批量禁用"不灰的不对称、两种不同原因的"分块为空"。这些状态在真实系统里要靠构造数据才能看到，评审时没人会为了看一眼文案去手工造五种状态的数据。

## 原型不负责什么

- **不是前端代码的起点。** 前端用 React + TypeScript 实现（工单 04 起），原型的 HTML/JS 不会被复制进去。它是一次性的评审载体，用完就只作为设计决策的留档。
- **不实现真实请求。** 所有数据写死在 `index.html` 顶部，字段名与 `api.md` 的响应体保持一致，方便照着对接口。
- **不规定视觉风格。** 配色和字体是为了让原型看起来像个真实工具、不至于影响判断，不构成对最终实现的约束。
