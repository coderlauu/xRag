# 《AI大模型Ragent项目》——项目启动指南

> 原文链接：https://t.zsxq.com/Hkh2u
> 所属分组：02-bootstrap-and-deployment 本地开发与模型部署环境

## 一句话概括

参考 Ragent 的启动链路遵循依赖拓扑：先启动并验证中间件，再注入模型密钥和实例隔离配置，随后启动主服务、可选 MCP Server，最后启动前端并用登录及真实请求验证整条链路。

## 核心内容提炼

### 1. 启动顺序来自依赖关系

Ragent 建议按以下顺序启动：

1. PostgreSQL、Redis、RocketMQ、RustFS 等中间件。
2. `RagentApplication` 主服务。
3. 可选的 `MCPServerApplication`。
4. Vue 前端（Node 开发服务器或预编译静态资源）。

关键不是机械记顺序，而是每一步都要在下游启动前证明已经就绪。容器处于 running、Spring 输出 `Started`、Vite 输出端口，都只是进程信号，不等价于业务健康。

### 2. 外部模型能力属于显式依赖

参考项目需要为 Chat、Embedding、Rerank 配置外部 AI 平台密钥。文章推荐环境变量注入，并明确警告不要提交真实密钥。

启动说明应区分：

- 没有密钥时应用是否拒绝启动。
- 某个 Provider 不可用时哪些功能降级。
- 本地验证需要哪些最小模型能力。
- 凭据由谁提供、如何轮换以及如何从日志中脱敏。

### 3. 共享中间件必须隔离命名空间

课程环境允许多人共用 Redis/RocketMQ，因此通过唯一实例名、Redis Key 前缀和消息消费组隔离。这个做法说明所有共享基础设施都需要明确的命名空间策略；不能只隔离 Redis，却让对象存储 Bucket、消息 Topic、数据库 Schema 或追踪服务继续冲突。

学习笔记不保留文章中展示的共享环境凭据。即使凭据出现在课程材料里，也不应复制进项目文档或提交历史。

### 4. 可选服务应明确降级语义

Ragent 在 MCP Server 未启动时允许主服务继续运行，并跳过工具注册。可选依赖的失败可以不阻断核心功能，但应：

- 以可识别状态暴露“能力不可用”。
- 避免用高严重级别日志制造长期噪音。
- 让健康检查区分核心就绪与可选能力缺失。
- 防止用户进入必然失败的功能路径。

### 5. 启动验证需要从进程走到用户路径

文章最后通过前端登录进入主界面作为体验验证，并给出数据库、前端 API 地址、Node 版本、端口占用等排查方向。更完整的验证应覆盖：

- 中间件连接及必要资源。
- 后端健康/就绪接口。
- 前端能访问后端。
- 一条代表性业务请求。
- 日志中没有被误当成“可忽略”的真实失败。

## 关键概念/术语

- 依赖拓扑：服务之间“谁必须先可用”的有向关系。
- 就绪检查（Readiness）：判断实例是否具备接受实际请求所需依赖和资源的检查。
- 可选依赖：缺失时只影响部分能力、不会阻断核心服务启动的依赖。
- 能力降级：依赖不可用时显式关闭部分功能并保留可用核心路径。
- 命名空间隔离：用实例名、前缀、数据库/Bucket/Topic 等边界避免共享环境互相污染。
- 密钥注入：在运行时从环境或密钥管理系统提供凭据，而非硬编码进源码。
- 冒烟验证：用最短代表性请求确认部署链路基本可用。

## 与 xrag 项目的关系

文章描述的是参考 Ragent，不是 xrag 当前启动方式。xrag 基线为：

- 本地中间件只有 PostgreSQL、Redis、MinIO，没有 RocketMQ、RustFS 或 Nacos。
- 后端只有 `com.app.Application`，默认端口 3001；没有独立 MCP Server。
- 前端是 React/Vite，使用 `pnpm@10.7.1`，不是 Vue/npm。
- 当前没有模型 Provider 配置，也没有登录业务；可验证路径是 `/api/v1/health`、`/api/v1/health/ready` 和前端健康占位页。
- xrag 的正确启动依据是根目录 README、Compose 和脚本，不是 Ragent 的端口、默认账号或 VM 参数。

Phase 0 健康检查应按 xrag 自身顺序执行：Compose 配置 → 三个本地依赖健康 → 必要 MinIO Bucket/数据库扩展 → 后端启动和 readiness → 前端构建/启动及后端连通。

## 值得注意的设计取舍/坑

- **不要把课程共享凭据复制到本地配置**：共享 Redis/RocketMQ 参数同时带来凭据泄露、数据碰撞和不可控稳定性；xrag 验证应优先使用本地隔离依赖。
- **日志中“可忽略的 ERROR”是可观测性债务**：真正可选的 MCP 缺失应表达为禁用状态或受控告警，否则会训练团队忽略 Error 日志。
- **外部 Provider 免费额度会变化**：价格和活动不是稳定启动前提；项目应把 Provider 能力和密钥状态作为配置，而不是文档中固定供应商承诺。
- **默认账号只适合演示**：`admin/admin` 不能出现在生产可达环境，初始化后应强制更改或完全禁止默认凭据。
- **端口和模块名会随上游变化**：文章自身已出现 MCP 端口描述不一致等迹象，复现 Ragent 时必须以固定 commit 的配置为准。
- **启动成功不等于端到端可用**：仅看到 Spring/Vite 日志会漏掉数据库扩展、对象存储 Bucket、跨域/API 基址和模型凭据问题。
