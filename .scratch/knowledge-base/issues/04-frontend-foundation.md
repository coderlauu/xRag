## 完成记录

目录约定：`api/`（client + errors + types）、`components/`（跨页面共用）、`pages/`（一页一文件）。路由用 `react-router` 8。

**做了工单清单之外的一件事，因为不做整条链路就是断的：配了 Vite 开发期同源代理。** 浏览器实测发现 `:5173` 直连 `:3001` 是跨源请求，后端没有 CORS 配置，请求被浏览器拦掉（`net::ERR_FAILED`），界面上显示"无法连接到服务器"——看起来像后端没启动，实际是同源策略。README 原本就写着"本地开发默认同源代理需自行配置"，这张工单正是配它的时机。选代理而不是给后端加 CORS：代理只影响开发期，加 CORS 是生产形态的决定，该走运维 Lane 和 ADR。代理目标用 `BACKEND_ORIGIN` 覆盖，默认 `http://localhost:3001`；README 已同步。

**错误映射集中在 `api/errors.ts` 一处**，页面只把捕获到的异常原样交给 `ErrorState`，**不许自己判断错误类型**——散到各页面就会出现同一个 429 在不同页面说法不同。

三处实现细节值得记：

1. **`AbortError` 原样抛出，不包装成网络错误。** 组件卸载、切换筛选都会主动取消请求，把它显示成"无法连接到服务器"是纯误报。轮询（工单 10）会大量触发这条路径。
2. **状态码兜底推断错误码。** 超过 `max-file-size` 的请求由 Tomcat/Spring 在进入控制器前就拒掉，返回的是容器默认错误页而不是 `{error, message}`，413 这一路尤其容易走到。已实测无响应体的 413 仍能映射出正确文案。
3. **响应体为空或非 JSON 时返回 `null` 而不是抛解析异常**，否则真正的错误会被 `SyntaxError` 掩盖。

**顺带对齐了配色**：`index.css` 的强调色从脚手架模板的紫色改成已确认原型的青绿（`#0d7a72` / 暗色 `#46b3a9`），`#root` 从 1126px 居中带边框的展示容器改成普通应用外壳——业务页面是列表和表格，居中文本会让每一页都要覆盖它。删掉了随之失效的 `App.css`。
