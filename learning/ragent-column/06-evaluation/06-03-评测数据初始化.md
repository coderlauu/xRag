# 《测评数据初始化》

> 原文链接：https://t.zsxq.com/1OfHs
> 所属分组：06-evaluation RAG 评测体系

## 一句话概括

评测前必须把被评环境初始化成一个可验证、可重建的固定状态，并确认知识库、分块、向量和意图树都已就绪；否则零分可能只是夹具没装好。

## 核心内容提炼

- 课程按“建知识库 → 上传并分块文档 → 构建意图树”初始化，三步有严格依赖顺序。
- 文档以稳定业务码命名，初始化产物保存业务码到运行时 ID 的映射；环境相关 ID 不提交 Git。
- 上传接口只触发异步分块，脚本结束不等于数据可检索。评测前要用明确的就绪条件确认每篇文档已产生分块。
- 批量上传逐项写入进度映射，支持从中断处继续；破坏性 reset 默认 dry-run 并要求显式确认。
- 意图到知识库的绑定可从 gold 文档分布推导，但这是一种课程便利做法，仍需人工检查边界描述和异常样本。

## 关键概念/术语

- **评测夹具**：为可重复测试准备的知识库、文档、意图树和配置。
- **就绪条件**：证明评测环境能被检索的可观测状态，而非“脚本没有报错”。
- **环境映射**：稳定业务标识与某个部署实例内部 ID 的对应关系。
- **重建清单**：从空环境恢复到目标评测状态所需的版本化步骤和输入。

## 与 xrag 项目的关系

- xrag 已有异步入库与文档 revision；初始化验收应绑定成功的 `ingestion_run`、文档 revision、分块/向量数量和启用状态。
- 评测知识库不能依赖开发者当前数据库的偶然内容。Step C 应选择独立 fixture、固定快照或可验证的种子流程。
- 意图树已经是完整 revision 快照，评测 run 应记录实际消费的 revision，而不是只写“当前意图树”。
- reset 评测数据属于破坏性操作，后续实现必须限定命名空间和目标，不能模糊删除共享知识库。

## 值得注意的设计取舍/坑

- 课程脚本不幂等是教学取舍；xrag 若在 CI/自动化环境重建夹具，应优先设计可重复执行或显式创建一次性隔离环境。
- “文档更新后重建意图树”不是普遍规律。xrag 的知识库绑定是显式配置，不应从样本投票静默改变生产路由。
- 只记录最终数量不够；需要对输入内容 hash、分块策略、Embedding 部署和代码版本建立关联。
