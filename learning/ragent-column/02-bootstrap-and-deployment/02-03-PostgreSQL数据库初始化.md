# 《AI大模型Ragent项目》——PostgreSQL数据库初始化

> 原文链接：https://t.zsxq.com/Ynima
> 所属分组：02-bootstrap-and-deployment 本地开发与模型部署环境

## 一句话概括

参考 Ragent 在 PostgreSQL 容器可用后，按“结构与扩展 → 基础数据”的固定顺序执行版本匹配的 SQL，并通过关键表、种子数据、pgvector 扩展和应用连接配置进行验证；升级环境则应走增量迁移而非重复初始化。

## 核心内容提炼

### 1. 初始化脚本有职责和顺序

Ragent 的参考脚本位于 `/resources/database`：

- `schema_pg.sql`：创建数据库对象、表、索引以及 pgvector 扩展。
- `init_data_pg.sql`：写入系统配置、用户/权限等业务种子数据。

必须先执行 Schema 再执行种子数据，否则会因为目标表不存在或约束未建立而失败。文章基于特定日期版本编写，实际执行时要以当前仓库脚本为准。

### 2. 客户端只是执行入口

TablePlus、Navicat、DBeaver、IDEA/DataGrip 都可以导入 SQL，工具不同不改变数据库初始化语义。更重要的验证不是界面显示“执行成功”，而是：

- 目标数据库、Schema、表和索引确实存在。
- `vector` 扩展已安装并可用。
- 关键种子数据可查询。
- 应用使用的主机、端口、数据库、用户和密码与初始化目标一致。

图形客户端适合人工探索，重复部署和 CI 最终仍应有确定、可失败退出的命令或迁移工具。

### 3. 首次初始化和版本升级不同

空数据库可以执行最新完整 Schema 与种子脚本；已有数据的环境不能简单重跑初始化或删库重建。文章建议使用版本间增量脚本并关注变更日志，以免丢失数据。

这一点揭示了“能初始化”与“可演进”的区别：项目一旦产生真实数据，就需要有序、可追踪、最好可回滚或可恢复的迁移流程。

### 4. 配置一致性是最后一道检查

Ragent 示例使用 `ragent` 数据库和 `postgres/postgres` 凭据。它们只适用于参考环境；数据库脚本成功而应用仍连接失败，常见原因是应用配置指向了另一数据库、端口或账号。

## 关键概念/术语

- Schema 脚本：建立扩展、表、约束和索引等数据库结构的脚本。
- 种子数据：系统首次运行所需的最小配置、角色或基础记录。
- pgvector 扩展：为 PostgreSQL 增加向量类型、距离运算符和相关索引能力的扩展。
- 全量初始化：面向空数据库建立当前完整状态的过程。
- 增量迁移：把已存在的数据库从一个已知版本推进到下一版本的有序变更。
- 数据库就绪：不仅进程接受连接，还满足应用所需扩展、结构、权限和基础数据条件。

## 与 xrag 项目的关系

当前 xrag 与参考 Ragent 的数据库状态必须明确区分：

- xrag `docker-compose.yml` 使用 `pgvector/pgvector:pg16`，数据库、用户和密码均为 `app`，不是 Ragent 的 `ragent` 和 `postgres`。
- xrag `application.properties` 默认连接 `jdbc:postgresql://127.0.0.1:5432/app`，与本地 Compose 一致。
- 当前仓库没有业务 Schema、种子数据或迁移工具；后端只有 JDBC 连接骨架。不能因为镜像包含 pgvector 就宣称扩展已经在目标数据库中 `CREATE EXTENSION`。
- Phase 0 的环境检查应分别验证 PostgreSQL 进程、应用账号连接和 `vector` 扩展状态，并把“尚无业务表”记录为预期基线而非运行失败。

## 值得注意的设计取舍/坑

- **镜像支持不等于数据库启用扩展**：`pgvector/pgvector` 提供扩展文件，但每个目标数据库通常仍需显式执行 `CREATE EXTENSION vector`。
- **手工 GUI 初始化不可重复审计**：人工操作容易漏脚本、执行到错误数据库或无法证明版本；进入业务开发后应选择迁移机制并纳入启动/部署流程。
- **种子数据与演示数据要分开**：生产必需配置、权限基线与课程演示账号的生命周期和安全要求不同，不应放在同一不可区分的初始化脚本中。
- **脚本文件名存在课程文本不一致**：文章前文使用 `init_data_pg.sql`，Navicat/DBeaver 小节写成 `init_data.sql`；执行时应以仓库实际文件为准。
- **初始化成功不能只查一张表**：还需验证扩展、约束、索引、权限以及应用账号的真实读写能力。
- **尚未确定的业务 Schema 不应提前复制**：Ragent 表结构是参考输入，xrag 应在 Phase 1 形成自己的领域模型与迁移，不直接导入参考库表。
