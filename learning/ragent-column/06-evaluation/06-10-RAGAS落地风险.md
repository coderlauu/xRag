# 《RAGAS 的坑》

> 原文链接：https://t.zsxq.com/8YZhT
> 所属分组：06-evaluation RAG 评测体系

## 一句话概括

LLM-as-judge 的分数会受模型偏好、随机性、结构化输出失败、费用预算和人工分歧影响，因此必须版本化、重复性验证、失败显式化并用人工样本校准。

## 核心内容提炼

- 同族 judge 可能偏好同族生成结果；课程建议固定 judge 或尽量使用不同模型族，避免换 judge 与换被评模型同时发生。
- 同一 runs 文件重复评分也会波动。课程用多轮均值压低噪声，并提醒小幅变化不能直接宣称改进。
- 中文 claim/statement 解析可能产生 NaN；批量失败降级、逐条隔离和重试能提高完成率，但不能把剩余 NaN 静默排除后只报漂亮均值。
- RAGAS 调用量远大于“样本数 × 指标数”的直觉，必须通过样本上限、单轮模式、复用录制和显式开关控制费用。
- Judge 会误判同义改写、枚举顺序、隐含事实和格式化答案。课程在逐样本 CSV 预留人工覆盖列，并重算汇总结果。

## 关键概念/术语

- **Self-preference bias**：模型对自身或同族输出的偏好。
- **评分方差**：被评输入不变时，judge 输出仍发生波动。
- **NaN / 不可评**：评分未产生有效值；它不是普通低分。
- **人工校准**：用预先定义的人工流程核对自动评分，而非随意改分。

## 与 xrag 项目的关系

- Step E 前应先构造一小组双人标注校准集，测 judge 与人工的一致率和常见偏差，再决定是否允许某项自动分成为门禁。
- 人工 override 必须记录 reviewer、时间、理由、原始分与新分，且不能覆盖原始观测；报告显示自动、人工和最终采用值。
- 多轮评分不是免费获得统计显著性。应保存每轮结果、均值、离散程度与样本数，A/B 比较尽量使用相同录制和配对样本。
- 费用守门应记录实际调用/Token/金额或可获得的等价用量，超预算中止后报告部分成功，而不是自动继续重试。

## 值得注意的设计取舍/坑

- 课程关于 3%~8% 偏置、3%~5% 方差和具体人民币成本属于场景估算，不是通用常数；xrag 必须以自己的模型、版本和数据实测。
- “固定 judge 后相对趋势就是真的”仍过强：被评输出风格改变也可能改变 judge 偏置，关键差异仍需人工复核。
- 自定义中文 Prompt 与默认 Prompt 的分数不能直接拼接成同一历史曲线；评测 Prompt 变化应开启新基线。
