# 问答对话页原型

> **PROTOTYPE — 一次性界面验证资产，不是生产实现。**

验证问题：在 Phase 3A 只有历史、改写、意图与歧义、还没有最终答案时，问答页应如何同时服务自然对话与链路验收？

原型提供三种结构不同的方案：

- A — Conversation + Inspector（2026-08-07 选中，2026-08-08 改判落选）
- B — Pipeline Workbench
- C — Focused Chat（**2026-08-08 已选择**，默认打开的就是它）

## 评审结论

2026-08-07 先选了 **A — Conversation + Inspector**；2026-08-08 在 3B Step B 审阅增量原型后
**改判为 C — Focused Chat**：中央单列 760px，对话列表与「本轮处理」在所有断点上都是抽屉。
A/B 继续保留为决策证据，但不再承载 3B 内容。

改判的完整记录与代价（`3A-UI-07` 走查作废）在
[ui-spec §12A / §14](../../../tech/qa-pipeline/conversation/ui-spec.md)。

## 3B 增量（2026-08-08，draft，待确认）

新增九个 `3B` 场景，验证的问题是：检索来源、工具四态与三类降级如何在不新增页面的前提下并入这一页。
规格是 [ui-spec §13](../../../tech/qa-pipeline/conversation/ui-spec.md)，产品语义冻结在
[PRD §12](../../../docs/prd/2026-08-07-qa-pipeline-prd.md)。

- 「本轮处理」抽屉拆成「本轮结果」（来源 + 工具）与「处理详情」（3A 验收信息）两组。
- 可点的活路径：工具确认 → 执行中 → 已完成；取消；失败后重试**重新出确认卡**；
  部分失败的重试与「就现有结果继续」。
- **3B 场景只在 C 方案上演示**（A/B 只是 3A 的决策留档），点 3B 场景会自动切到 C 并说明原因。
- 走查时注意抽屉是**关着的**：来源摘要行、无结果、部分失败、工具卡都必须在消息区看得见，
  一次不开抽屉也不该丢信息。这是选 C 之后最该验的一条。

启动：

```bash
python3 -m http.server 4174 --directory prototype/qa-pipeline/conversation
```

打开：

```text
http://127.0.0.1:4174/?variant=C
```

底部可切换演示场景；最下方悬浮切换器或键盘 `←` / `→` 切换 A/B/C。输入框聚焦时不会拦截方向键。
