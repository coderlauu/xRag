# ADR 0001：在当前 xrag 基线上独立建设系统

- 状态：已接受
- 日期：2026-07-25

## 背景

仓库历史中曾存在一套已删除的 TypeScript 实现，学习材料又配有独立的 `nageoffer/ragent` Java 项目。两者都包含可借鉴的产品和架构思路，但当前 xrag 已明确重置为 Java/Spring Boot 后端与 React 前端的空白脚手架。

如果把旧实现或 Ragent 当作迁移源，后续文档、数据模型和模块边界会受其既有约束；如果独立建设，则需要重新完成需求和架构决策，但每项决策都能由 xrag 的实际目标与验证结果驱动。

## 决策

xrag 在当前仓库基线上独立设计和实现：

- 已删除的 TypeScript 实现不恢复、不迁移，只在需要时用于历史对比。
- `nageoffer/ragent` 是课程配套参考实现，不作为 xrag 的代码基线，也不直接复制其配置、Schema 或模块结构。
- 学习笔记中的方案只有经过 xrag 的需求确认、取舍分析和验证后，才可成为实现决策。
- 当前 Java/Spring Boot 与 React 脚手架作为后续建设起点；具体业务架构仍按阶段决策。

## 后果

正面影响：

- xrag 不继承参考项目中未经验证的约束、版本漂移和隐含业务假设。
- 产品文档、术语、ADR、测试和实现可以保持同一套项目语境。
- 参考实现升级不会自动改变 xrag 的行为。

代价：

- 不能用“课程代码已经实现”代替 xrag 自己的需求分析和验收。
- Provider 路由、知识入库、问答链路和评测等能力需要逐步重新实现。
- 对参考实现的结论必须记录所检查的版本，并与 xrag 当前状态分开描述。

## 未在本决策中确定

本 ADR 不决定数据库 Schema、向量模型、分块策略、模型 Provider、本地部署方式或模块接口；这些事项需等对应业务需求和证据明确后再决策。
