## 完成记录

产出 [test-matrix.md](../../../tech/knowledge-base/test-matrix.md)：8 个功能域共 106 条用例 + 9 条手工验收项 + PRD §8 七条验收标准的追溯表。

**几条值得单独说明的设计**：

1. **手工项的判定标准全部做成二元的。** M-01（最高优先级，唯一可能推翻技术方案的用例）没有采用"用 JFR 看堆峰值曲线"这种要人目测的办法，而是用 `-Xmx256m` 跑：堆上限远小于"30MB 文件 + SigV4 摘要放大"所需，能跑完就证明请求体确实没被整体读进堆，OOM 就是失败。JFR 数据仍然采集，但只作留档，不作判定依据。
2. **DEL-08 是这份矩阵里最反直觉的一条**：`max(chunk_index)` 查询必须**包含**已删除分块，否则新分块序号会与已删除分块撞车。它证明了 `deleted = false` 不是可以机械套用到每条 SQL 上的模板——把纪律当模板套，恰好会在这里出错。
3. **DEL-12（向量表不变量）被要求作为每个集成测试类的通用收尾断言**，而不只是一条独立用例。任何操作破坏了这条不变量都应该在那个测试里立刻暴露，而不是等跑到 DEL-12 才发现。它在 PRD 验收追溯表里出现三次，因为"向量被正确清理"这件事在 PRD 里被表述成了三个不同角度的要求，实现上收敛到同一条不变量。
4. **明确写了"集成层必须用真实 Postgres，不能用 H2"**并给了理由：本模块相当一部分正确性落在数据库里（部分唯一索引、check 约束、`vector(1024)`、HNSW），H2 一条都不支持，用它跑出的绿灯没有意义。
5. **§11 单列了"这份矩阵没有覆盖什么"**：检索效果（要 Phase 3/4）、多实例并发（前提已知不成立，ADR 0002 记录了失效点）、性能压测（PRD 没有性能目标，没有判定标准的压测只会产生没人看的数字报告）、权限（PRD 非目标）。
