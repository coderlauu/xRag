## 2. Objective

把 3A 产出的不可变检索动作变成真实召回结果与受控工具调用，并让来源、降级与工具状态对用户可察觉。
3B 仍不生成答案。

## 3. Scope

### In Scope

- 关键词派生表、应用侧分词、存量回填。
- 三通道检索、按动作激活、RRF 融合、`chunk_id` 去重、两段截断。
- `RerankClient` 三态与不补齐语义。
- 部分知识库失败的显式状态与只重跑失败目标的重试。
- 原生 Function Calling、工具白名单、Schema 复核、副作用二次确认。
- 问答页来源区与工具区的前端实现（布局已是 C，本段不再改布局）。

### Out Of Scope

- 答案生成、SSE、停止、排队、限流（3C）。
- 新增 Chat 供应商；DashScope 原生 Rerank adapter 的实现（Phase 2 工单 23，见 §7）。
- 意图树的任何变更——3B 不新增 MCP 叶子类型，工具清单来自配置。
- 检索质量评测与调参（Phase 4）。

## 5. Lanes

### Lane 产品

- 守住 PRD §12 的六类语义不被实现"顺手简化"，尤其是"确认前不执行"与"不补齐 topN"。
- 冻结 3B 归一化失败文案闭集（工具失败、检索超时、库不可用），不让异常 message 漏进文案。
- 走查来源、工具四态与三类降级的界面表达，回写矩阵 `3B-UI-*`。
- 不重开界面方案讨论：布局已是 C，来源/工具位置已在 ui-spec §13 冻结。

### Lane 后端

- `com.app.qa.retrieval` 与 `com.app.qa.tool` 两个新子包，依赖方向遵守架构 §19.1。
- 只通过 `ChunkSearchPort` 访问知识库表；不在问答模块拼 chunk SQL。
- 只通过 `com.app.ai` 的 `RerankClient` / `ChatClient` 调模型；不碰 Provider、routing、runtime。
- 所有模型调用与工具调用在数据库事务外；事务只覆盖本地状态转换。
- 新增调度类组件（回填批处理）必须带 `enabled` 开关（ADR 0002 单实例假设）。

### Lane 前端

- 来源区、工具区与确认卡按 ui-spec §13 实现；**不复制原型代码**。
- 关键事实必须落在消息区：抽屉默认关闭，来源摘要行、无结果、部分失败、工具卡都要在关着时可见。
- 确认卡不抢焦点，Tab 先到取消，`Esc` 只关抽屉不取消工具。
- 工具返回按纯文本渲染，不解析 HTML/Markdown 链接与图片。

### Lane 测试

- 80 条 `3B-*` 全部要有落点；`A` 项在对应工单关闭前必须有测试方法。
- 收费 Provider 由显式环境变量守门，缺变量 skip 不判 failed。
- 正面断言两张派生表行集合一致——漏写不会报错，只能靠测试拦。
- 副作用工具的"零外部调用"用可观测假工具断言调用次数为 0，不靠人眼看日志。

### Lane 运维

- 显式声明 Hikari 池大小（10，与 Postgres `max_connections` 联动才可调大），登记检索并行度、topK、rerank 输入上限与工具超时。
- **换分词词典 = 重建 `document_chunk_keyword` 全表**，写进部署文档而不是代码注释。
- CI 默认假检索、假 Rerank、假工具；真实链路不进默认 CI。
- 回填批处理的开关与运行方式登记在部署 README。

## 9. 风险与护栏

| 风险 | 护栏 |
|---|---|
| 两张派生表漏写一张，关键词静默少召回 | 行集合一致性测试正面断言；写入点单一 |
| 切词器索引期/查询期不一致 | 同一个 Bean、同一份词典；版本进配置指纹与启动日志 |
| 并行检索打爆连接池，症状像"检索变慢" | 并行度 < 池大小启动校验；两个执行器不共享队列 |
| 定向与全局同时激活，去重后等于只查一次 | 按动作激活，契约测试断言全局通道零 SQL |
| 有副作用工具在确认前被执行 | 数据库 check 约束 + 假工具调用计数断言，两层都拦 |
| 异常 message 漏进用户文案或 Prompt | 归一化闭集 + 标记串扫描；`failureCode` 不接受自由文本 |
| 3B 顺手把答案生成做了 | 矩阵 `3B-E2E` 断言无答案生成调用；ui-spec §13.1 第 1 条 |
| 真实 Rerank 依赖迟迟不到，演示被拖住 | 见 §7：Noop 路径本身就是要交付的产品状态 |
