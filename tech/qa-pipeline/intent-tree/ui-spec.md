# 界面规格：意图树管理页（Phase 3A 基线）

- `status`: approved（2026-08-07）
- `route`: `/intent-tree`（建议）
- `prd`: [AI 知识问答核心链路 PRD](../../../docs/prd/2026-08-07-qa-pipeline-prd.md)
- `prototype`: [三方案可点击原型](../../../prototype/qa-pipeline/intent-tree/index.html)
- `scope`: 3A 意图树查看、增删改、启停、知识库绑定与父子一致性
- `selected_direction`: C — Route Canvas

## 1. 设计问题

意图树既是运营配置，又是全链路路由表。页面不能只让用户“看见一棵树”，还必须让他在修改前回答：

1. 这个叶子与兄弟节点有什么区别，模型凭什么匹配它？
2. 它最终绑定哪个 xrag 知识库？
3. 停用或删除父节点会影响哪些后代？
4. 保存失败时，当前运行配置有没有被部分修改？

原型提供三个结构不同的方向：

- **A — Tree + Inspector**：左侧树形导航，右侧详情/编辑器，稳定、可扩展。
- **B — Operational Outline**：全宽层级表格，字段横向比较优先，编辑走侧边抽屉。
- **C — Route Canvas（已选择）**：节点关系图 + 右侧检查器，结构最直观但大树和键盘操作成本最高。

## 2. 与现有应用的关系

- 顶部导航顺序：`问答 / 知识库 / 意图树 / 诊断`。
- 建议路径 `/intent-tree`，不藏在知识库详情下：一棵意图树会跨多个知识库，是独立的全局路由配置。
- 页面沿用 xrag 绿色强调色和紧凑工具型密度，不做低信息量“大卡片仪表盘”。
- 3A 只管理 KB 与 SYSTEM 类叶子；MCP 类型及工具绑定在 3B Step B 更新规格后加入。

## 3. 信息架构

```text
/intent-tree
  ├─ 页头
  │    ├─ 标题 / 配置快照状态
  │    ├─ 搜索
  │    └─ 新增根节点
  ├─ 树/大纲/画布主视图
  │    ├─ 节点层级
  │    ├─ 启停状态
  │    ├─ 节点角色 / 叶子类型
  │    └─ 绑定知识库
  └─ 节点检查器
       ├─ 基本信息
       ├─ 匹配规则（description + examples）
       ├─ 路由绑定
       ├─ Prompt 追加片段
       ├─ 状态与影响范围
       └─ 保存 / 停用 / 删除
```

## 4. 页头与全局状态

### 4.1 页头

必须包含：

- 标题：`意图树`；
- 说明：`只有启用的叶子参与问题匹配；匹配描述会直接影响路由准确率。`；
- 搜索框：按名称、完整路径、匹配描述和知识库名称过滤；
- `新增根节点`按钮；
- 最近刷新时间与刷新按钮。

不提供：

- 一键“让 AI 优化整棵树”；
- Prompt 原文编辑器；
- 拖拽任意换父节点；
- 导入/导出、历史版本恢复或多人发布流。

### 4.2 配置状态

页头用紧凑状态表示：

| 状态 | 文案 | 行为 |
|---|---|---|
| 已同步 | `当前显示最新配置` | 正常编辑 |
| 有未保存修改 | `有未保存修改` | 离开/切节点前确认 |
| 保存中 | `正在保存…` | 禁止重复提交，不冻结浏览 |
| 版本冲突 | `配置已被更新，请比较后重试` | 保留本地表单，不自动覆盖 |
| 加载失败 | `意图树加载失败` | 整体重试，不展示假树 |

## 5. 节点模型在界面中的表达

### 5.1 节点角色

| 角色 | 是否参与匹配 | 必须字段 | 可有子节点 |
|---|---|---|---|
| 组织节点 | 否 | 名称 | 是 |
| KB 叶子 | 是 | 名称、匹配描述、至少一个正向示例、知识库绑定 | 否 |
| SYSTEM 叶子 | 是 | 名称、匹配描述、正向示例、系统场景标识 | 否 |

- “叶子”由是否有子节点决定，不靠固定层级枚举判断；两层和三层分支可以并存。
- 组织节点新增第一个子节点后仍是组织节点；叶子一旦有路由绑定，不允许直接再加子节点，必须先明确转换并清理绑定。
- 3A 不展示 MCP 叶子选项，避免出现尚不可执行的分支。

### 5.2 树节点行

最少展示：

- 展开/收起；
- 名称；
- 角色标签：`组织` / `KB` / `SYSTEM`；
- 状态：`已启用` / `已停用` / `祖先已停用`；
- KB 叶子的绑定知识库短名；
- 后代数量或叶子数量（组织节点）；
- 更多菜单：新增子节点、启停、删除。

状态不能只靠颜色。`祖先已停用` 与节点自身 `enabled=false` 必须区分，避免用户误判恢复方式。

### 5.3 完整路径

- 检查器顶部展示完整路径，例如 `物流与配送 > 跨境物流 > 清关流程`。
- 搜索结果仍保留路径上下文，不能只显示同名叶子。
- 两层叶子的品类语义就是它自身；三层叶子的品类语义是最近的组织父节点。具体歧义算法由 Step C 冻结，
  但界面必须让这两种形态可辨认。

## 6. 三种布局方向

### 6.1 A — Tree + Inspector

```text
┌──────────────────────────────┬───────────────────────────────┐
│ 树形导航 42%                 │ 节点详情 / 编辑器 58%         │
│ 搜索结果保持祖先路径         │ 分组表单 + 底部固定操作栏      │
└──────────────────────────────┴───────────────────────────────┘
```

优点：

- 层级与单节点复杂表单同时清楚；实现和键盘可达性可控。
- 未来 3B 加 MCP、3C 加安全提示只扩展右侧分组，不破坏主结构。

代价：

- 兄弟节点 `description` 的横向比较不如 B；可通过搜索和“查看兄弟摘要”缓解。

### 6.2 B — Operational Outline

结构：全宽树形表格，每行展示名称、角色、状态、绑定、描述摘要和更新时间；点击行在右侧抽屉编辑。

优点：适合一次扫视大量节点、查未绑定或停用项；运营密度最高。

代价：窄屏横向列太多；描述与示例编辑需要跳入抽屉，层级感弱于 A。

### 6.3 C — Route Canvas（已选择）

结构：主区域是从 DOMAIN 向叶子展开的关系图，状态和类型用节点形状/标签表达；右侧检查器编辑。

优点：跨分支关系和影响范围最直观，演示效果强。

代价：大树易变成平移缩放工具；排序、搜索结果、键盘操作和移动端都更复杂，不适合作为第一版默认管理器。

## 7. 节点详情与编辑器

### 7.1 基本信息

| 字段 | 规则 |
|---|---|
| 名称 | 必填；同一父节点下不能重名；用于人类导航，不等同匹配描述 |
| 父节点 | 只读展示；3A 不支持直接换父节点 |
| 节点角色 | 创建时选择组织 / KB / SYSTEM；已有绑定或子节点时不能随意转换 |
| 状态 | 展示自身状态与祖先状态；启停通过独立确认动作，不混在普通保存中 |

### 7.2 匹配规则

**匹配描述 `description`**：

- KB/SYSTEM 叶子必填；组织节点可选，仅供运营说明，不参与匹配。
- 输入区上方固定说明：`写清什么问题应该来这里，以及它和兄弟节点的区别。知识库简介不会自动代替此字段。`
- 失焦时可提示过短、只复述节点名称、与兄弟描述高度相似等风险；3A 不做 AI 自动改写。

**正向示例 `examples`**：

- 叶子至少一条，建议 3~5 条；每条是一个真实用户问法。
- 支持逐条新增、编辑、删除和键盘排序；3A 不支持批量粘贴智能拆分。
- 示例不得包含秘密或真实个人信息，界面给出提示但不声称自动脱敏。

### 7.3 路由绑定

KB 叶子：

- 从现有知识库中单选一个，显示名称、ID 缩略值、启用状态和分块数摘要（若 API 提供）。
- 已删除/禁用/不可检索的知识库不能作为新绑定；已有绑定失效时显示阻塞警告，节点不能启用。
- 不允许直接输入 Milvus Collection 或任意表名。

SYSTEM 叶子：

- 选择受控系统场景标识，例如 `GREETING`；具体闭集由 Step C/API 冻结。
- 3A 不允许运营者输入任意可执行代码或完整系统 Prompt。

### 7.4 Prompt 追加片段

- 字段名显示为 `回答附加规则（后续生成阶段使用）`，而不是技术名 `promptSnippet`。
- 说明：`它只会追加到系统规则，不能替换安全规则；3A 保存但尚不执行。`
- 多行文本；字符上限由 Step C 冻结，界面不预填未经确认的数值。
- 组织节点不显示此字段。

### 7.5 保存

- 普通字段修改使用底部固定 `取消修改` / `保存节点`。
- 保存成功后更新当前节点和树行摘要；失败保留输入。
- 切换节点、搜索跳转或离开页面前，如有未保存内容，提示 `放弃修改 / 留在此处`。
- 保存不包含启停与删除，避免一个普通字段错误和级联操作混在同一事务/确认中。

## 8. 创建节点

### 8.1 新增根节点

- 从页头进入轻量弹层，只允许创建组织节点。
- 字段：名称、运营说明、初始状态（默认停用）。
- 保存后选中新节点并在检查器继续完善。

### 8.2 新增子节点

- 从父节点行或检查器进入，弹层顶部明确 `将在「完整路径」下创建`。
- 选择组织 / KB / SYSTEM；默认停用，配置完整后再显式启用。
- 若父节点本身是已有路由绑定的叶子，操作被阻止并解释：`该节点已有执行绑定，不能直接添加子节点。`

## 9. 启停与级联

### 9.1 停用叶子

确认文案：

> 停用后，新问题将不再匹配到「清关流程」。已有对话和历史记录不会被删除。

### 9.2 停用父节点

必须展示影响范围：

```text
停用「跨境物流」及其子树？
将停用 4 个节点，其中 3 个是当前可匹配的叶子。
```

- 唯一主操作：`停用整个子树`。
- 不提供“只停父节点”按钮。
- 服务端若检测到后代版本变化，整体失败；界面刷新影响范围后让用户重试。

### 9.3 启用

- 叶子启用前检查祖先、绑定与必填字段。
- 组织节点启用时提供明确二选一：`仅启用当前节点` / `启用整个已配置完整的子树`。
- 子树内不完整叶子不得被跳过后显示整体成功；应先列出阻塞节点并停止操作。

## 10. 删除与逻辑删除

- 删除动作放在更多菜单的危险区，与“停用”分开。
- 根节点可以作为树的一级节点，但系统保留根（若 Step C 选择单一虚拟根）不可删除；界面根据 API 能力隐藏/禁用。
- 删除叶子确认展示绑定目标和影响。
- 删除父节点确认展示整个子树节点数、启用叶子数与绑定知识库数；主按钮 `删除整个子树`。
- 删除采用逻辑删除；文案不承诺可由当前页面恢复，因为恢复功能不在 3A。
- 一致性校验或版本冲突时不部分删除，保留树并显示：`意图树已变化，本次删除未执行。请刷新影响范围后重试。`

## 11. 搜索、筛选与空态

### 11.1 搜索

- 匹配名称、路径、匹配描述和绑定知识库名称。
- 结果在原结构中展开并高亮匹配节点，保留祖先上下文。
- 清除搜索恢复用户搜索前的展开状态。

3A 可选紧凑筛选：全部 / 已启用 / 已停用 / 配置不完整。若后端不能精确支持，不在前端用当前已加载片段
伪造全局筛选。

### 11.2 空态

**整棵树为空**：

- 标题：`还没有意图节点`
- 说明：`先创建一个业务域，再在下面添加绑定知识库的叶子。`
- 操作：`创建第一个业务域`

**搜索无结果**：展示搜索词与 `清除搜索`，不显示创建同名节点的快捷按钮，避免误建重复规则。

**未选择节点**：检查器展示树规模摘要和操作提示，不默认选中第一个节点造成误编辑。

## 12. 错误与冲突状态

| 场景 | 用户反馈 | 表单/树处理 |
|---|---|---|
| 名称重复 | `同一父节点下已存在同名节点` | 聚焦名称，不清空其他字段 |
| KB 绑定失效 | `绑定的知识库不可用，请重新选择后再启用` | 保持节点停用 |
| 叶子必填缺失 | 字段级错误 + 顶部摘要 | 不提交 |
| 父子一致性失败 | 展示哪个后代阻塞 | 不部分应用 |
| 保存版本冲突 | `该节点已被更新` + 刷新/保留本地选择 | 默认保留本地表单 |
| 树加载失败 | 整体错误态 + 重试 | 不展示上次树为“最新” |
| 网络中断 | 非阻塞提示；保存动作可重试 | 未确认成功前保持 dirty |

## 13. 响应式与无障碍

- 1440px：A 方案树与检查器并排；检查器底部操作栏可见。
- 1024px：树 40% / 检查器 60%，隐藏次要列。
- 720px：树为主列表，点击节点进入独立检查器页面；返回保持展开与滚动位置。
- 375px：节点行允许两行，更多菜单触控目标至少 44px；不依赖横向拖动画布完成核心管理。
- 树使用标准 tree/treeitem 语义；左右键折叠/展开，上下键移动，Enter 选择。
- 弹层/抽屉有焦点约束与返回；危险确认默认焦点不落在危险按钮。
- 标签和文字共同表达状态，不能只靠绿/灰/红。

## 14. 原型演示场景

原型底部“场景控制”不是产品的一部分，至少覆盖：

1. 正常树与 KB 叶子编辑；
2. 创建子节点并显示默认停用；
3. 停用父节点的子树影响确认；
4. 启用时存在配置不完整的后代；
5. 删除父节点的逻辑删除确认；
6. 保存版本冲突并保留输入；
7. 搜索同名“退货政策”并保留路径；
8. 375px 节点列表 → 详情返回。

方案通过 `?variant=A|B|C` 切换，左右方向键可轮换；焦点在输入/文本域时不拦截方向键。
