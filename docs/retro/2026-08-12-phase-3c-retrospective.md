# 复盘：Phase 3C 生成 + 流式 + 任务管控

- `phase`: Phase 3 / 3C 子里程碑（`2026-08-12`）
- `status`: [里程碑状态](../status/2026-08-12-phase-3c-generation-streaming.md)

只记录会改变下一阶段做法的事情。功能清单与测试数字见里程碑状态，不在这里重复。

## 1. 原子工单没有变成原子提交

3C 在 Step C 拆成 16 张原子工单，依赖图也明确要求逐张闭合；实际 Git 历史却把后端 01~09、12~14、
16 共 12 张工单合成一个 5119 行新增的提交，前端 10/11 和矩阵 15 再各一个提交。任务书能解释工作，
但提交历史已经无法按工单二分、回退或复核。

**教训**："一张工单一个可验证变化"必须同时约束工作过程和 Git 历史。Phase 4 每张工单完成时就提交，
提交前在干净 HEAD 上跑该工单的目标测试；如果最终需要 squash，也先保留可审计的中间提交或明确记录
squash 映射，不能只留下三次大批量落库。

## 2. 单一结算边界把并发问题从约定变成了不变量

完成、停止、等待超时、流失败、推送背压、关停都可能同时抵达。如果每个入口各自"判断一下状态再做
清理"，正确性依赖所有未来维护者永远记得相同顺序。3C 把它们收进 `TaskSettlement.trySettle`：数据库
CAS 首胜，只有胜者保存消息、取消订阅、释放许可并发送终态；V11 再用唯一索引和 check constraint
兜住数据层。

1000 轮三方竞态不是为了追求一个大数字，而是证明所有入口确实共享同一结算点。

**继续保持**：遇到"多个入口争夺一次性副作用"，优先设计唯一结算 seam 和可观测资源计数，不在每个
入口复制防重逻辑。Phase 4 的评测任务若支持取消、超时和重试，应直接复用这一思路。

## 3. 浏览器状态组合发现了自动化没有说清的产品错误

排队中取消原本显示"已有部分"，但此时模型尚未订阅，不可能有任何正文。服务端状态机、SSE 顺序和
组件测试都可以是绿的，只有把"排队 × 停止 × 零正文"这个组合走到页面上，文案矛盾才显现。

**教训**：UI 验收不能只按 happy path 或单一状态列举，要把阶段、终止原因、是否已有正文、是否落库
做状态组合。确定性夹具适合把罕见竞态稳定复现；夹具的职责必须限制在网络时序与返回值，不能复制生产
页面逻辑，否则会再次得到自洽的假证据。

## 4. 证据必须写清“证明了什么”，不能只写 passed

3C 同时有三层证据：假模型自动化证明编排、协议和竞态；本地夹具驱动的真实页面证明交互状态；Phase 2
的真实 DashScope 测试证明 Provider adapter 能流式工作。三者合起来仍不等于"真实模型经过完整 RAG
链路后的答案质量达标"。

**教训**：Phase 4 的每个指标必须同时记录被测对象、数据集 revision、模型版本、Prompt 版本和执行环境。
"真实 HTTP"、"真实页面"、"真实模型"是三个独立维度，状态文档不得用其中一个词替代另两个。

## 5. 阶段状态在实现完成后发生漂移

3C 三个实现提交已经落地，任务书和矩阵也写成 16/16、62/62，但父计划顶部仍称"Step D 第一前沿
01/02"，README 仍称"答案生成、流式任务管控待建"。这使任何只读入口文档的人都会得到错误结论，
直到 Step G 才被发现并纠正。

**教训**：Step G 负责总结与关闭，不应是第一次更新阶段状态。以后每个 Step D/E/F 闸门关闭时，至少
同步父计划 metadata 和 README 的能力概览；Step G 再负责证据边界、递延项与下一阶段准入。

## 6. 计划中的深模块约束确实压住了实现复杂度

Controller 只跨 `GenerationTasks.submit/stop`，没有接触队列、模型订阅、许可和结算细节；前端也只
消费独立的问答 SSE 事件闭集，没有把 `ChatStreamEvent` 或内部诊断对象直接投影出去。这使后端可以
单独压力测试并发语义，前端可以用确定性夹具验证交互，两边不需要复制彼此的状态机内部实现。

**继续保持**：Phase 4 先找一个能隐藏数据集装载、批量执行、指标计算和结果持久化的深模块 seam，
再设计页面与任务工单。不要从控制器端点或某个评测框架的类结构开始搭模块。

## 7. Phase 4 要带走的具体动作

1. 一张工单对应一个可验证提交；关闭工单前在干净 HEAD 上复核。
2. 每关闭 D/E/F 一个闸门，同步父计划 metadata 与 README 能力概览。
3. 评测证据记录数据集、知识库、模型、Prompt 四类 revision，不允许只记一个总分。
4. 先定义"链路正确"、"检索质量"、"生成质量"和"人工偏好"各自证明什么，再选指标与框架。
5. 真实模型调用显式守门并限制样本/费用；默认 CI 继续使用确定性假 Provider。
