# 《评估集没建好，RAG 评测都是白搭》

> 原文链接：https://t.zsxq.com/YzTo8
> 所属分组：06-evaluation RAG 评测体系

## 一句话概括

评估集的价值不在条数，而在覆盖、标注口径和可追溯性：每条样本必须说明该不该检索、应命中什么、期望答成什么样，以及它属于哪个风险切片。

## 核心内容提炼

- 随机抽线上 query 会遇到高频意图挤压长尾、缺少 gold label、隐私外泄三类问题，不能直接作为可提交的评估集。
- 课程样本包含 query、两级意图、`requires_rag`、must/nice 文档集、自然语言 reference、难度、陷阱类型和指标路由。
- `requires_rag` 决定样本该进入检索指标还是拒答/过召回行为指标；没有它会把正确拒答误算成检索失败。
- 期望文档使用跨环境稳定的业务码，而不是数据库主键；must 与 nice 区分核心证据和补充证据。
- reference 必须写成可直接回答用户的自然语言事实，不应写“应推荐……”之类元指令，否则会系统性干扰语义评分。
- 小型主力集适合日常回归，全量集适合正式基线和切片分析；小集不能证明长尾意图稳定。

## 关键概念/术语

- **Gold set**：经标注确认的相关文档或证据集合。
- **Reference / ground truth**：用于比较答案内容的参考答案，不等同于唯一措辞。
- **Must / nice**：必须覆盖的核心证据与可选的扩展证据。
- **数据污染**：评测答案、样本或等价信息进入被评模型训练、Prompt 调试或知识库，导致分数虚高。

## 与 xrag 项目的关系

- xrag 不能只保存当前数据库 ID；评估样本需要稳定业务标识，并能解析到本次知识库 revision 的具体文档/分块。
- 首版应同时保留 RAG、SYSTEM、工具和明确不可回答样本，否则只会评“能搜到的问题”，看不到误拒、过召回和工具路由错误。
- 线上 bad case 可作为候选来源，但进入仓库前必须脱敏、重写、复标，并记录来源许可；不得直接上传用户问题给外部 judge。
- 多子问题 turn 不能硬压成一个单意图 gold。样本粒度和评分粒度需在 Step C 明确。

## 值得注意的设计取舍/坑

- 课程的 20/150 条与意图分布只适用于其电商教学集，不能当 xrag 的固定规模或真实流量分布。
- 双人标注和冲突裁决比单纯增加样本更重要；若标注本身错，指标会把正确行为判为回归。
- reference、知识库和业务规则会演进，三者必须共同版本化；只给数据集文件名加 `v1` 不足以保证可复现。
