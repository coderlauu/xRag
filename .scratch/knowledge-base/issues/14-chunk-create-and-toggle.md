# 14 — 分块新增与单条启用/禁用

**What to build:** 用户能手动插入一个新分块（把被稀释的关键短句单独拎出来），也能把质量差的分块单条禁用而不删掉它。

**Blocked by:** 13（分块查看与编辑）

**Status:** ready-for-agent

- [ ] 后端 `POST /api/v1/documents/{docId}/chunks`，三重前置校验缺一不可：文档存在未删除（否则 `404`）→ 文档不在 `RUNNING`（否则 `409`）→ **文档 `enabled=true`**（否则 `409 INVALID_STATE`）
- [ ] 第三条校验的必要性写进代码注释：新增分块会立刻写向量参与检索，父文档禁用时就出现"文档整体不参与检索、但里面新加的这段却能被检索到"的矛盾
- [ ] `chunkIndex` 缺省时取 **`max(chunk_index) + 1` 而不是 `count(*)`**——分块可以被删除，`count` 会小于实际最大序号，用 `count` 会算出与现存分块冲突的序号
- [ ] 指定 `chunkIndex` 时**不重排**其他分块的序号（`chunk_index` 只是排序展示字段、允许重复，重排是一次大范围写入，代价与收益不成比例）
- [ ] 新增后文档 `chunk_count` 递增
- [ ] 后端 `PATCH /api/v1/chunks/{chunkId}/enabled`：
  - **启用时**才校验父文档 `enabled`（不通过 → `409 INVALID_STATE`，前端提示"请先启用文档"）
  - **禁用时不校验**（禁用不需要父文档处于任何特定状态）
  - 已是目标状态 → 直接返回（幂等）
  - 启用 → 重算 Embedding 写入；禁用 → 物理删除向量
- [ ] 前端：分块新增表单（可指定插入位置）+ 单条启用/禁用开关
- [ ] 集成测试（**关键**）：建 10 个分块（序号 0~9），删掉序号 5 和 8 的，再新增一个不指定序号的，确认新分块序号是 **10** 而不是 8
- [ ] 集成测试：给禁用状态的文档新增分块返回 `409 INVALID_STATE`
- [ ] 集成测试：禁用状态文档下的分块，单条启用返回 `409`；单条禁用正常成功
- [ ] 集成测试：重复禁用一个已禁用分块，向量表行数与该分块状态都不变
- [ ] `./mvnw -q -B verify` 与 `pnpm build && pnpm lint` 通过
