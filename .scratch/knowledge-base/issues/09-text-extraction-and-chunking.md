# 09 — 文本提取与分块算法

**What to build:** 给定一个文件，得到一串分块。纯本地字符串处理，没有 UI、没有数据库、没有网络调用——因此可以被单元测试**完整**覆盖，这是本模块唯一能做到这一点的部分，值得把测试写扎实。

**Blocked by:** 03（Tika 依赖）

**Status:** ready-for-agent

- [ ] Tika 文本提取，支持 `.txt` `.md` `.pdf` `.docx` 四种格式
- [ ] `FIXED_SIZE` 策略：按字符数硬切，相邻分块重叠 `overlap` 个字符
- [ ] `RECURSIVE` 策略：按分隔符优先级递归切分（默认 `["\n\n", "\n", "。", ". ", " "]`），先用最高优先级切，超长片段再用下一级切，最终仍超长的硬切
- [ ] 每个分块算出 `charCount`、`tokenCount`（启发式：中文 1 字≈1 token、英文 4 字符≈1 token、其他 2 字符≈1 token）、`contentHash`（SHA-256）
- [ ] `tokenCount` **只用于展示**，不参与任何逻辑判断
- [ ] 单元测试覆盖边界：空文档、只有空白字符的文档、单字符文档、长度恰好等于 `chunkSize`、长度等于 `chunkSize + 1`、`overlap = 0`、`overlap = chunkSize - 1`
- [ ] 单元测试验证 `RECURSIVE` 真的在段落边界切分（构造一段有明确段落结构的文本，断言切点落在 `\n\n` 处而不是中间）
- [ ] 单元测试验证一个没有任何分隔符的超长字符串也能被切开（递归到最后必须硬切，不能返回一个超长分块或死循环）
- [ ] `overlap >= chunkSize` 的参数组合被拒绝（否则会无限循环或产生无意义的重复分块）
- [ ] `./mvnw -q -B verify` 通过
