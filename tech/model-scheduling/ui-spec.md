# 界面规格：模型调度诊断页

- `status`: approved（2026-07-28）
- `route`: `/diagnostics`（扩展现有诊断入口）
- `prd`: [大模型调度引擎 PRD](../../docs/prd/2026-07-28-model-scheduling-prd.md)
- `prototype`: [三方案可点击原型](../../prototype/model-scheduling/index.html)
- `scope`: 只读调度诊断；不包含 Provider/模型 CRUD、密钥管理或聊天产品
- `selected_direction`: A — Trace Console

## 1. 设计问题

诊断页要让单用户运维者在不查看 Prompt 和模型输出的情况下回答三个问题：

1. **现在能调用谁？** Provider/模型支持哪些能力，熔断状态是什么。
2. **这次为什么选了它？** 初始候选、过滤原因和最终顺序是什么。
3. **中途发生了什么？** 每个 attempt 是重试还是故障转移，流在何时提交，最终为何成功、降级、失败或取消。

界面不是业务聊天页，也不是实时监控大屏。它服务于“某次调用出问题后能够快速复盘”，同时保留全局健康概览。

## 2. 与现有应用的关系

- 顶部导航继续使用现有 `xrag / 知识库 / 诊断` 外壳，不新增顶级“模型管理”导航。
- 现有 `/diagnostics` 的后端存活探测保留为页面顶部的应用健康摘要。
- 调度诊断内容放在同一路由中，不修改知识库页面层级。
- 第一版不要求调用详情独立路由。桌面端可用分栏，窄屏可用整页覆盖或抽屉。

建议页面内部使用两个视图：

- `调度总览`
- `最近调用`

调用详情从“最近调用”进入，不单独作为第三个导航项。

## 3. 信息架构

```text
/diagnostics
  ├─ 应用健康摘要
  ├─ 调度总览
  │    ├─ Provider / 模型能力
  │    ├─ 熔断状态
  │    └─ 最近异常摘要
  └─ 最近调用
       ├─ 过滤与搜索
       ├─ 逻辑调用列表
       └─ 调用详情
            ├─ 最终结果
            ├─ 候选与过滤
            ├─ Attempt 时间线
            ├─ 流式关键时刻
            └─ 脱敏诊断字段
```

## 4. 页面共同区域

### 4.1 页头

必须包含：

- 标题：`模型调度诊断`
- 副标题：`只记录路由与调用事实，不保存 Prompt、文档正文或模型输出`
- 最近刷新时间
- `刷新`按钮
- 数据保留提示：`保留 7 天或最近 10,000 次调用`

不得出现：

- 新增 Provider
- 编辑模型
- 设置 API Key
- 清空全部记录
- 手动重置熔断

这些操作都不在 Phase 2 第一版范围内。

### 4.2 应用健康摘要

现有后端存活状态用紧凑横条展示，不抢占主视觉：

| 状态 | 文案 | 色彩语义 |
|---|---|---|
| 可用 | `后端可用` | 绿色 |
| 探测中 | `正在探测后端…` | 中性/加载 |
| 不可用 | `后端不可用` + 脱敏错误摘要 | 红色 |

后端不可用时：

- 页面保留上次成功加载的调度数据并标记“可能已过期”，若没有缓存则进入整页错误态；
- `刷新`仍可用；
- 不伪造 Provider 状态。

### 4.3 数据新鲜度

- 正常：`刚刚更新` / `2 分钟前更新`
- 超过 5 分钟未刷新：显示 `数据可能已过期`
- 页面不做秒级自动跳动；页面可见时每 30 秒只刷新 overview，标签页隐藏时暂停。调用列表仅在首次进入、筛选变化或用户手动刷新时重新加载。

## 5. 调度总览

### 5.1 总览摘要

摘要数字最多四项，避免仪表盘堆叠：

1. 当前可用候选数；
2. OPEN 熔断数；
3. 最近 24 小时发生过故障转移的调用数；
4. 最近 24 小时失败/流中断次数。

数字必须可下钻到对应列表过滤结果。原型允许用静态数据演示，正式实现不得展示无法解释口径的百分比“健康分”。

口径与下钻固定为：

- 当前可用候选数：`enabled + CONFIGURED` 且对应能力 breaker 允许调用的 deployment-capability 单元；点击后过滤本页 Provider/模型能力视图，不冒充某个具体命令的 RoutePlan。
- OPEN 熔断数：当前 JVM registry 中主状态为 OPEN 的故障域；点击后过滤 breaker 视图。
- 发生过故障转移的调用数：点击后以 `failoverOccurred=true` 重新请求 calls。
- 失败/流中断次数：点击后以重复 outcome `FAILED + STREAM_FAILED` 重新请求 calls。

调用类摘要必须请求后端精确筛选，不能只过滤当前已加载的一页。

若 `diagnosticsDroppedSinceStart` 或 `diagnosticWriteFailuresSinceStart` 大于 0，在摘要条下显示“部分调用诊断可能缺失”的非阻塞警告及两个进程内计数；它不占用上述四个主指标，也不能把模型能力本身标为失败。

### 5.2 Provider / 模型能力视图

每个故障域以 `Provider / 模型 / 能力` 为最小展示单元。必须展示：

- Provider 与模型显示名；
- 稳定模型 ID 的缩略值；
- 支持能力；
- 所属服务等级；
- 是否启用；
- 熔断状态；
- 最近一次状态变化时间；
- 当前是否允许调用；
- 最近结果摘要。

同一模型支持多个能力时，Chat OPEN 不得让 Embedding 看起来也 OPEN。

### 5.3 熔断状态

| 状态 | 视觉 | 必须说明 |
|---|---|---|
| `CLOSED` | 绿色、`正常` | 允许调用 |
| `OPEN` | 红色、`已熔断` | 不允许调用；显示打开原因和预计/条件性恢复信息 |
| `HALF_OPEN` | 橙色、`恢复探测` | 是否已有探测占用 |
| 禁用 | 灰色、`配置禁用` | 与 OPEN 严格区分 |
| 未配置 | 灰色虚线、`未配置` | 不得显示成故障 |

页面第一版只读，不提供强制打开、强制关闭或手动重置动作。

### 5.4 最近异常摘要

只展示低基数、可行动的事实：

- `ark / qwen-plus / CHAT：5xx 后已切换`
- `siliconflow / rerank / RERANK：已降级为未重排`
- `local / qwen / STREAM_CHAT：提交后中断`

不展示原始错误体、Prompt 或模型输出。

## 6. 最近调用

### 6.1 筛选

必须支持：

- 时间范围：最近 1 小时、24 小时、7 天；
- 能力：全部、Chat、流式 Chat、Embedding、Rerank；
- 服务等级：全部、Economy、Balanced、Quality；
- 最终结果：全部、成功、降级、失败、取消、流中断；
- Provider；
- 内部请求 ID / 脱敏 Provider 请求 ID 精确搜索。

不提供 Prompt、用户问题或文档正文搜索。

Provider 筛选表示“该 Provider 曾发出真实 attempt”，因此会命中首选失败后已切换的调用和 mixed Embedding；它不是只按最终贡献者筛选。

筛选变化后：

- 页码回到第一页；
- 空结果显示当前筛选摘要和“清除筛选”；
- 筛选和视图同步到 URL query；当前选中 call ID 只保留在页面状态。

### 6.2 列表列

桌面端建议列：

| 列 | 内容 |
|---|---|
| 时间 | 逻辑调用开始时间，精确到秒 |
| 结果 | 成功、降级、失败、取消、流中断 |
| 能力 / 等级 | 例如 `STREAM_CHAT · QUALITY` |
| 实际路由 | 唯一贡献者显示 `Provider / model`；mixed Embedding 显示“多个 deployment”；无贡献者但有 attempt 时显示“最后尝试：Provider / model”；未产生 attempt 时显示 `—` |
| 过程 | `1 attempt`、`重试 1 次`、`切换 1 次`、`Noop` |
| 首个有效块 | 仅流式能力显示，其他为 `—` |
| 总耗时 | 右对齐、等宽数字 |
| 请求 ID | 缩略显示，可复制内部 ID |

列表默认按时间倒序。点击整行打开详情；行内不放多个小操作按钮。

### 6.3 最终结果字典

| 内部概念 | 中文标签 | 说明 |
|---|---|---|
| `SUCCEEDED` | 成功 | 最终完成，可能发生过重试/切换 |
| `DEGRADED` | 已降级 | 例如 Rerank Noop；不能显示为普通成功 |
| `FAILED` | 失败 | 未向下游提交有效内容，最终没有可用结果 |
| `CANCELED` | 已取消 | 调用方主动取消 |
| `STREAM_FAILED` | 流中断 | 已提交部分内容，之后失败；文案必须提示答案不完整 |

列表必须同时表达“最终结果”和“过程”。例如最终成功但切换过时：

> `成功` + `切换 1 次`

不能只显示绿色成功而隐藏首选模型失败。

## 7. 调用详情

### 7.1 详情头部

展示：

- 最终结果标签；
- 能力与服务等级；
- 开始时间、结束时间和总耗时；
- 唯一实际贡献 Provider/模型；mixed Embedding 展示全部贡献 deployment；无贡献者但有 attempt 时明确标为“最后尝试”，不能伪装成实际贡献；
- 内部请求 ID；
- 唯一贡献 attempt 的脱敏 Provider 请求 ID；其他 attempt 的脱敏 ID 只在对应时间线项展示；
- 是否流式、是否已提交；
- 隐私提示：`未保存输入和输出正文`。

`STREAM_FAILED` 必须在头部出现醒目但克制的警告：

> 生成中断。已显示的内容来自同一个模型，但可能不完整；系统没有在提交后切换模型。

### 7.2 候选与过滤

展示本次调用开始时的候选快照：

| 候选 | 能力 | 等级 | 状态 | 结果/过滤原因 |
|---|---|---|---|---|
| `ark / qwen-plus` | Chat | Quality | 进入候选链 | 排序第 1 |
| `local / qwen` | Chat | Economy | 已过滤 | 服务等级不匹配 |
| `ark / text-embedding` | Embedding | — | 已过滤 | 能力不支持 |
| `siliconflow / qwen` | Chat | Quality | 已过滤 | 熔断 OPEN |

过滤原因使用固定分类文案，不直接展示内部异常：

- 能力不支持
- 服务等级不匹配
- 模型身份不匹配
- 配置禁用
- 配置不完整
- 熔断不允许
- 调用方约束不匹配
- 总预算不足

### 7.3 路由与 Attempt 时间线

时间线以逻辑调用开始为 0 点，按真实发生顺序展示：

```text
0 ms      路由完成：2 个候选
18 ms     Attempt #1 · ark/qwen-plus · 开始
641 ms    Attempt #1 · SERVER_ERROR · HTTP 503
647 ms    故障转移到候选 #2
661 ms    Attempt #2 · siliconflow/qwen · 开始
1,204 ms  首个有效业务块
1,216 ms  下游提交
3,842 ms  完成
```

路由完成、熔断许可拒绝、重试安排/等待、故障转移、预算耗尽和调用终止来自持久化 route event；页面不得根据 attempt 间隙补造。每个真实 attempt 展示：

- attempt 编号；
- `重试`或`故障转移`来源；
- Provider/模型；
- 熔断许可前后状态；
- 开始、首事件、首有效业务块、下游提交和结束时间；
- 归一化错误类型及 HTTP 状态；
- 结果：成功、失败、限流、超时、取消、空流或提交后流中断。

原始 Provider 错误体不展示。

### 7.4 流式关键时刻

流式详情单独显示三个指标：

| 指标 | 中文 | 用途 |
|---|---|---|
| first upstream event | 首个上游事件 | 网络/协议开始有响应 |
| first meaningful chunk | 首个有效业务块 | 模型开始产生可交付结果 |
| downstream commit | 下游提交 | 透明故障转移的最终边界 |

非流式调用不显示空卡片，直接隐藏本区。

### 7.5 Embedding 详情

不得展示输入文本。只显示：

- 固定模型身份；
- 等价部署候选；
- 输入条目数和批次数；
- 维度；
- 按批次输入范围展示实际贡献 Provider/模型；
- 贡献 deployment 列表，以及是否发生同模型等价部署 mixed execution；
- 条数、index、维度校验结果。

若因模型身份不匹配而无候选，明确显示：

> 为保护既有向量空间，系统没有切换到其他同维模型。

### 7.6 Rerank 详情

不得展示 query 或候选正文。只显示：

- 候选条目数和 top-N；
- 实际 Rerank Provider/模型；
- 是否真实执行；
- `rerankApplied=false` 时的降级原因；
- Noop 不能显示为 Provider attempt 成功。

## 8. 交互规则

### 8.1 刷新

- 点击后保留当前视图和筛选；
- 加载期间按钮显示进行中且避免重复触发；
- 失败时保留已有内容并出现非阻塞错误条；
- 没有旧内容时使用整页错误态。

### 8.2 查看详情

- 桌面宽屏：推荐列表与详情双栏，选中行保持高亮；
- 普通桌面：可使用右侧抽屉；
- 移动窄屏：详情覆盖内容区，顶部提供明确返回；
- 关闭详情后列表筛选与滚动位置保持。

### 8.3 复制请求 ID

- 只允许复制内部请求 ID和已脱敏的 Provider 请求 ID；
- 成功后出现短暂 `已复制`反馈；
- 不提供“复制完整诊断 JSON”，避免未来无意带出敏感字段。

### 8.4 空态

| 场景 | 标题 | 辅助文案 | 动作 |
|---|---|---|---|
| 从未有调用 | 暂无模型调用 | 当 Phase 2 能力被调用后，这里会出现路由和 attempt 记录 | 刷新 |
| 筛选无结果 | 没有符合条件的调用 | 当前筛选：流式 Chat、失败、最近 1 小时 | 清除筛选 |
| 无 Provider 配置 | 尚未配置模型候选 | 通过配置文件登记非敏感模型信息，并用环境变量注入密钥 | 查看配置文档 |
| 无 OPEN 熔断 | 当前没有熔断中的候选 | 所有已启用故障域目前允许调用 | 无 |

## 9. 状态组合矩阵

下表是实现和评审必须逐格覆盖的状态，不得只看“成功/失败”两种：

| 最终状态 | 中间失败 | 是否提交 | 是否换模型 | 页面表达 |
|---|---:|---:|---:|---|
| 成功 | 否 | 视能力 | 否 | 成功，1 attempt |
| 成功 | 是 | 提交前 | 是 | 成功 + 切换 N 次；时间线展示失败 |
| 已降级 | 是或无候选 | 否 | Noop | 已降级，未执行 Rerank |
| 失败 | 是 | 否 | 可有 | 所有候选耗尽或永久错误 |
| 已取消 | 否/竞态 | 任意 | 否 | 调用方取消，不影响熔断 |
| 流中断 | 是 | 是 | 否 | 保留部分内容，明确不完整 |

附加维度：

- 熔断：CLOSED / OPEN / HALF_OPEN / 禁用 / 未配置；
- 能力：Chat / 流式 Chat / Embedding / Rerank；
- 详情：有候选 / 全部被过滤 / 有 attempt / 无 attempt；
- 数据：新鲜 / 过期 / 刷新失败；
- 页面：加载 / 有数据 / 空 / 错误。

## 10. 原型三方案

原型在同一个页面外壳中提供三种结构，使用 `?variant=` 切换：

### A — Trace Console（已选定）

- 最近调用是主视觉；
- 左侧调用列表，右侧固定详情和 attempt 时间线；
- Provider/熔断状态在顶部压缩为摘要条；
- 适合核心任务“从一条失败或变慢的调用开始排查”。

优点：排障路径最短、上下文持续可见。

代价：全局 Provider 能力矩阵需要切到总览或打开次级面板。

### B — Operations Overview

- 摘要指标、Provider 能力矩阵和熔断状态是主视觉；
- 最近调用位于下方；
- 调用详情使用抽屉。

优点：适合先观察系统整体状态。

代价：追踪单次调用需要多一次点击，容易出现“漂亮但不够深”的仪表盘。

### C — Route Map

- 以能力和服务等级为中心展示候选链；
- 右侧展示实时/近期异常事件；
- 调用详情从某条候选链或事件进入。

优点：最直接解释“某类请求会选谁”。

代价：对第一次来排查具体请求的人不如 Trace Console 直观。

三种方案必须在布局和信息层级上明显不同，不能只换颜色。项目所有者可以选择一套，也可以明确组合，例如“A 的双栏详情 + B 的能力矩阵”。

评审结论（2026-07-28）：项目所有者选择 A — Trace Console。正式前端应采用“最近调用列表 + 固定调用详情/attempt 时间线”的双栏信息层级；B/C 不进入正式实现，仅作为本次取舍的原型证据。A 顶部保留紧凑 Provider/熔断摘要，但不引入 B 的大面积 KPI 仪表盘。

## 11. 原型专用控制

以下仅存在于原型，不进入正式页面：

- 底部浮动方案切换器；
- `←` / `→` 键切换方案；
- 演示场景选择：
  - 正常成功；
  - 同步故障转移；
  - 提交前流式切换；
  - 提交后流中断；
  - 熔断 OPEN；
  - Rerank Noop。
- “PROTOTYPE / 一次性验证资产”标识。

## 12. 响应式与可访问性

- 1280px 以上可使用双栏；低于 960px 列表与详情改为单栏/抽屉。
- 低于 720px 时表格转为调用卡片，不强制横向滚动查看关键状态。
- 所有状态不能只靠颜色表达，必须有文字标签和图形/点状辅助。
- 点击行可以用键盘聚焦并通过 Enter 打开详情。
- 浮层关闭支持 Escape，焦点返回触发元素。
- `prefers-reduced-motion` 下禁用旋转和大幅位移动画。
- 时间、耗时和计数使用等宽数字，长模型名与请求 ID允许截断但必须有完整可访问名称。

## 13. 文案基线

| 场景 | 推荐文案 |
|---|---|
| 最终成功但切换过 | `调用成功；首选模型失败后已切换 1 次` |
| 所有候选失败 | `所有合格模型均未完成调用` |
| 永久错误 | `请求或模型配置有误，系统未尝试其他模型` |
| 流提交后中断 | `生成中断，已显示的内容可能不完整` |
| 用户取消 | `调用已取消；不会影响模型健康状态` |
| Embedding 拒绝其他模型 | `为保护既有向量空间，未切换到其他模型` |
| Rerank Noop | `未执行重排序，结果保持原召回顺序` |
| 数据过期 | `诊断数据可能已过期，请刷新后再判断当前状态` |

避免：

- `智能路由成功`
- `系统已自动修复`
- `模型宕机`
- `无感切换`

这些文案要么不可验证，要么掩盖了实际发生的故障。
