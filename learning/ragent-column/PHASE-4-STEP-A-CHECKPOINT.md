## 2. Step A 收敛结论

1. **评测对象是一次可追溯执行，不是一段孤立答案。** 答案、实际使用的有序证据、阶段结果和性能时间点
   必须属于同一个 turn/trace；课程的“生产 SSE + 第二次检索旁路”只能算近似证据，不作为 xrag 首选基线。
2. **指标按阶段分层。** 意图/动作、检索、工具、生成、行为、性能、费用和可靠性分别记录；不设一个
   “RAG 总分”替代分项事实。
3. **确定性指标与 judge 指标分层运行。** 默认 CI 只跑有界、确定性、无真实模型费用的门禁；真实被评模型
   和 LLM-as-judge 由显式守门任务运行，允许部分成功并记录实际用量。
4. **评估数据与被评配置共同版本化。** 数据集文件版本不够，还必须绑定知识库输入、意图树、Prompt、
   被评模型、judge、指标实现和代码版本。
5. **自动分数是证据，不是裁决。** 高风险样本与自动低分必须可人工复核；人工覆盖保留原始值、复核人、
   时间与理由，不能静默改写历史结果。
6. **先做可审计产物，再决定界面。** 机器可读 JSON/JSONL、Markdown/CSV 和失败下钻足以支撑首版闭环；
   是否需要评测页面提交 Step B 裁决，不把漂亮看板当评测体系前置。
7. **框架晚于口径。** RAGAS 是候选适配器，不是既定选型；先冻结样本、指标资格、版本身份、费用与
   人工校准边界，再用当前版本小样本原型验证中文与 API。

## 3. 七个必须回答的问题

### 3.1 最小不可变身份

建议把可比较的一次观测定义为以下身份的组合，而不是单个自增 `run_id`：

| 维度 | 最少记录内容 | 原因 |
|---|---|---|
| 样本 | dataset id/version + sample id + 内容 hash | 防止同名样本内容变化 |
| 被评执行 | turn id / trace id + code commit | 保证证据和回答同源 |
| 知识输入 | fixture/snapshot id + 文档 revision/content hash | 区分知识变化与算法变化 |
| 路由 | intent tree revision | 解释意图和知识库选择 |
| 生成 | Prompt/template version + 实际模型/部署 | 解释答案变化 |
| 评分 | metric implementation + judge/embedding + judge Prompt | 解释分数变化 |

具体主键、表和快照格式留到 Step C；Step A 只确认这些维度不得丢失。

### 3.2 分层指标及不可混用边界

| 层 | 第一批候选事实/指标 | 不能冒充什么 |
|---|---|---|
| 意图/动作 | 子问题级 Top-1、gold action 覆盖、澄清/拒答正确性 | 不能证明检索或答案正确 |
| 检索 | Doc/Chunk Hit@K、Recall@K、MRR/nDCG、降级率 | 不能证明模型实际使用或答案忠实 |
| 工具 | 工具选择、参数、确认、执行终态、结果校验 | 不能塞进文档 Hit@K |
| 生成 | faithfulness、relevance/correctness 候选、引用/兜底规则 | 不能证明知识库事实本身正确 |
| 端到端行为 | 成功、正确拒答、误拒、过召回、失败/取消 | 不能由成功样本均值替代 |
| 性能/费用 | 排队、客户端 TTFT、阶段耗时、总耗时、输出速率、Token/金额 | 不能把总耗时叫 TTFT |

### 3.3 三类评测数据能证明什么

| 数据类型 | 能证明 | 不能证明 / 风险 |
|---|---|---|
| 无 reference | 运行稳定性、性能、行为分布；部分无参考语义信号 | 不能证明事实正确或 gold 召回 |
| 弱标注/合成 | 快速扩大覆盖、发现明显回归 | 标签可能继承生成模型偏差，不能当人工金标 |
| 人工金标 | 在标注规范内验证检索、路由和答案要求 | 成本高、会过时；仍需冲突裁决与一致率 |

防污染最低要求：样本来源登记、脱敏与许可检查；开发调参集、发布验证集和保留盲测集分开；线上 bad case
进入固定集前重写与复标；评测内容不得无授权进入训练、Prompt 示例或外部 judge。

### 3.4 如何定位退化来源

同一次 run 同时保存阶段结果、阶段时延、模型/配置身份和逐样本指标；比较时先检查身份是否可比，再按
`意图 → 动作 → 检索 → 工具 → 生成 → 行为/性能` 下钻。overall 只用于发现趋势，根因判断必须落到切片、
单条事实和必要的人工复核。执行失败、不可评、跳过和有效低分必须分开计数。

### 3.5 LLM-as-judge 如何守门

- 固定并记录 judge/embedding、Prompt、框架版本、参数、重试和并发；Prompt 或 judge 变化开启新 baseline。
- 先在双人标注的小型校准集上测一致性和常见误判，再决定哪些指标可作门禁。
- A/B 使用相同录制、相同 judge 和配对样本，保存逐轮结果与离散程度；不以单次小幅变化宣称改进。
- 限定样本、调用、Token/金额与墙钟预算；超预算停止并报告部分结果，不自动无界重试。

### 3.6 RAGAS 与中文适用性

当前结论是 **candidate / 未选定**。课程证明了一种可运行方式，但其 API、指标内部 Prompt、算法口径、
方差与费用数字都绑定具体版本和模型。一手资料支持“指标按输入条件选择、逐样本异步评分、记录成本和使用
人工校准”，并不支持把课程阈值当通用标准。Step D 前需要用当前锁定版本和 xrag 中文样本做小型原型，
同时保留自有意图、行为、工具、性能和费用指标。

### 3.7 首版是否需要评测页面

**Step A 建议：首版不新增页面，以版本化报告产物与受控 API 为先。** 理由是主要消费者目前是 CI、研发和
项目所有者，JSON/JSONL + Markdown/CSV 已能完成守门、下钻和确认；页面会提前引入筛选、权限、敏感正文
展示与长期产品维护。Step B 必须让项目所有者显式选择“报告/API”或“评测页面”，本建议不代替裁决。

## 4. 与 xrag 当前实现对照

| 评测所需事实 | 当前可复用落点 | 缺口 |
|---|---|---|
| 同一次问答身份 | `qa_turn`、生成 task、SSE/HTTP 契约 | 缺统一评测 run/sample 绑定 |
| 意图 | `qa_intent_match` + 固定 `intent_revision_id` | 缺 gold 与逐子问题评分模型 |
| 检索 | `qa_turn_retrieval`、source/target/funnel、rerank 降级 | 缺稳定 gold 业务码和被模型实际消费证据快照 |
| 工具 | action、tool call、确认与终态 | 暂无真实 `ToolExecutor`，首版可只验证协议样本 |
| 生成/模型 | assistant message、generation task、AI diagnostics | 缺 Prompt 版本和统一模型身份快照 |
| 性能 | stage latency、AI route event、客户端可观测 SSE | 缺统一起点定义和客户端 TTFT 录制 |
| 知识版本 | 文档 revision、content hash、ingestion run | 缺一次 run 的知识库集合快照身份 |

## 5. Phase 3 递延项归属

| Phase 3 项 | Phase 4 处理 |
|---|---|
| RAG 检索与答案质量评测 | **进入主范围** |
| 模型横向对比 | 进入可比性设计；是否首版实现留 Step B/C |
| 真实供应商 3C 端到端 | 建 baseline 前做一次显式计费、可追踪的守门验证 |
| 真实工具执行 | 继续不在范围；无真实执行器前只评工具协议/路由夹具 |
| 多实例、SSE 重放、WebSocket、再生成、流式 Markdown | 继续不在 Phase 4 评测主范围，不借评测顺手实现 |
| 3B 响应外壳与原文预览缺口 | 继续作为既有契约缺口，不在 Step A 扩范围修复 |

## 7. 不可照搬项

- 不采用两次独立检索拼接答案与证据作为 xrag 的优先方案。
- 不照搬课程的 20/150 条规模、业务分布、目标阈值、方差百分比和费用估算。
- 不把 RAGAS 五指标覆盖范围扩张成完整 xrag 链路质量。
- 不把内部数据库主键、知识库正文或用户原问题默认复制进长期报告或发送给外部 judge。
- 不因课程用 Python 独立仓库，就在 Step A 提前决定 xrag 的部署边界。
- 不用人工 override 覆盖原始自动分，也不静默排除 NaN、失败或不可评样本。
