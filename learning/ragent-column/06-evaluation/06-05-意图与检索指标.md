# 《从意图到检索：指标拆解》

> 原文链接：https://t.zsxq.com/txWHU
> 所属分组：06-evaluation RAG 评测体系

## 一句话概括

意图准确率、Hit@K、Recall@K 和 MRR 分别回答路由是否正确、是否至少找到一项、是否找全、首个相关结果是否靠前；它们口径不同，不能用一个指标替代另一层。

## 核心内容提炼

- 意图 Top-1 Accuracy 是预测首位意图与 gold 意图完全相等的样本比例；课程把非 RAG 意图也纳入，因为它们同样需要正确路由。
- 检索指标只统计 `requires_rag=true` 且存在 gold 文档的样本，避免把正确拒答或无标注样本塞进分母。
- `Hit@K` 只看 Top-K 是否至少命中一个相关文档；`Recall@K` 看 gold 集被覆盖的比例；`MRR@K` 看第一篇相关文档的倒数排名。
- 同时观察多个 K 能区分“完全没召回”和“召回了但排得靠后”，为 TopK 或 rerank 调整提供方向。
- 文档级自建 Recall 与 RAGAS `context_recall` 不同：前者对稳定 ID 做集合运算，后者用 judge 判断上下文是否覆盖 reference 信息。

## 关键概念/术语

- **Top-1 Accuracy**：首选预测与标签一致的比例。
- **Hit@K**：Top-K 至少含一个 gold 的样本比例。
- **Recall@K**：每条样本 Top-K 覆盖 gold 集的比例，再按既定聚合口径汇总。
- **MRR@K**：首个相关结果倒数排名的均值。
- **Macro / micro aggregation**：先按样本或切片平均，与把所有命中合并计算会得到不同结果。

## 与 xrag 项目的关系

- xrag 一个 turn 可拆多个子问题、每个子问题保留多个意图，课程的单标签 Top-1 不能直接覆盖该结构；需要分别定义子问题级、turn 级和动作级正确性。
- 检索结果包含向量/关键词/RRF/精排阶段。应明确指标读取哪个阶段的有序列表，避免拿精排后 Top-5 与粗召回 gold 口径混算。
- `rerank_applied=false` 是显式降级事实，报告应把降级样本单独切片，不能与完整精排样本直接混均值。
- 工具路由不是文档检索，需另设工具选择、参数与结果正确性指标，不能塞进 Hit@K。

## 值得注意的设计取舍/坑

- 课程对多子问题只取首个意图，无法发现后续子问题路由错误。
- MRR 只关心第一个相关结果，不衡量多个必要证据是否齐全；多证据问题必须配合 Recall/nDCG 或自定义覆盖指标。
- 必须把空 gold、映射失败、正确拒答和执行失败分开计数；静默跳过会让分数虚高。
