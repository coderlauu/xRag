# 《AI大模型Ragent项目》——本地开发环境搭建

> 原文链接：https://t.zsxq.com/YllVK
> 所属分组：02-bootstrap-and-deployment 本地开发与模型部署环境

## 一句话概括

本文给出参考 Ragent 项目的最小开发机准备流程：安装支持 Spring Boot 3 的 JDK 17 和 IntelliJ IDEA，通过 Git 克隆持续迭代的仓库，确认 Maven 与项目 JDK 配置一致，并以成功完成 Maven 构建作为基础环境可用的第一道证据。

## 核心内容提炼

### 1. 先锁定项目声明的运行时

Ragent 基于 Spring Boot 3，要求 JDK 不低于 17。IDE 自身使用的 JDK、项目 SDK、Maven 导入器和命令行 `java`/`mvn` 可能指向不同版本，排错时要分别确认，不能只看 IDEA 界面里一个选项。

IDEA 2023+ 是课程推荐工具，不是源码构建的硬依赖；社区版可以完成基础开发。真正可复现的环境要求应由构建文件和命令行验证决定。

### 2. 使用 Git 保留更新能力

课程建议从 GitHub 或 Gitee 镜像克隆，而不是下载 ZIP。原因不只是操作方便：Git 工作区保留远端历史、分支和差异，后续可以明确识别“参考项目更新了什么”，避免覆盖本地研究记录。

克隆方式（SSH 或 HTTPS）取决于本机凭据；SSH 地址并非功能要求。

### 3. Maven 构建是环境探针

项目导入完成不代表环境成功。至少应从命令行执行 Maven 验证，确认：

- Java 版本符合 `pom.xml`。
- Maven 能解析父 POM 和依赖。
- 源码能够编译，测试与插件能够运行。
- IDEA 与命令行使用同一套项目设置。

文章提醒某些 IDEA 与 Maven 版本组合可能存在兼容问题，但版本问题应根据实际错误和项目构建声明诊断，不宜笼统地把 Maven 新版本都判定为不兼容。

### 4. 开始工作前先同步参考基线

Ragent 仍在迭代，阅读源码或复现实验前应记录当前 commit，并在需要时拉取更新。没有 commit 标识的“我运行过 Ragent”无法与后续结果稳定对照。

## 关键概念/术语

- Project SDK：IDE 为项目编译、索引和运行选择的 JDK。
- Maven Runtime：执行 Maven 导入和构建的 Maven/JDK 组合，可能与 IDE 进程本身不同。
- 可复现基线：能用仓库 commit、运行时版本和明确命令重新得到相同结果的环境状态。
- 上游仓库：作为学习和比较来源的 Ragent Git 仓库，不是 xrag 的代码来源分支。
- 构建探针：用一次最小、确定的构建命令验证工具链与依赖是否可用。

## 与 xrag 项目的关系

xrag 是独立仓库，不能照搬文章的“克隆 Ragent 后开发”步骤。当前基线已经明确：

- `backend/pom.xml` 使用 Spring Boot 3.4.1 和 Java 17，与文章的 JDK 主版本要求一致。
- xrag 后端没有 Maven Wrapper，当前验证依赖本机 `mvn`；这会使 Maven 版本更容易漂移，是需要在后续决定是否补齐的脚手架问题。
- xrag 还有 React/Vite/TypeScript 前端，开发机除 JDK/Maven 外还需要 Node.js 与锁定为 `pnpm@10.7.1` 的 pnpm。
- Ragent 只作为参考项目。若为验证而克隆，应放在独立临时目录并记录 commit，不放进 xrag 工作树，也不把其 README 的命令当作 xrag 启动命令。

## 值得注意的设计取舍/坑

- **IDE 成功不等于 CI 成功**：IDE 可能使用缓存、内置 Maven 或不同环境变量；最终必须以仓库脚本和命令行构建为准。
- **“JDK 不低于 17”不等于任意高版本都兼容**：项目通常声明一个目标版本；用更高 JDK 运行 Maven 仍需实际验证插件和依赖。
- **不应凭经验降级 Maven**：文章的版本提示来自特定 IDEA/项目组合。xrag 应先记录 `mvn -version` 和实际失败，再决定是否固定版本或引入 Wrapper。
- **拉取最新与复现实验存在张力**：学习最新内容时可同步上游，但做验证和记录时必须固定 commit，否则结果会在不知情下变化。
- **工作区隔离很重要**：参考 Ragent 的本地配置、生成物和数据库脚本不能混入 xrag，避免把参考项目状态误判为 xrag 能力。
