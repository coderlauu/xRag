# 13 — 分块查看与编辑

**What to build:** 用户能按原文顺序浏览一份文档的分块，发现某个分块把一段完整描述切断了，直接改掉它的内容，改完后向量同步更新。

这是「手动干预」这个永久兜底能力的第一块（PRD §4.4：自动分块无法覆盖所有情况，手动干预不是临时方案）。

**Blocked by:** 10（异步入库——要先有分块才能查看）

**Status:** done `2026-07-25`

### 实现时发现的一处界面规格缺口（已修，需要你过目）

ui-spec §6 原本只写了保存后的**两种**反馈："内容变了 → 向量已更新"、"内容没变 → 未重新计算向量"。但还有第三种：**内容变了、但这个分块是禁用的**。禁用分块本来就没有向量、编辑也不写向量（CHK-22 就是这么要求的），此时说"向量已更新"是**错的**——用户会以为这段内容已经能被检索到了，而它恰恰不能。

补了第三条文案「已保存。该分块已禁用、不参与检索，因此没有计算向量。」，弹层里的说明文字同样按启用状态分叉。ui-spec §6 与原型的 `saveChunk()` 已同步改掉，三处一致。

### 几处设计取舍

- **分页排序键是 `(chunk_index, id)` 而不是只有 `chunk_index`**。`chunk_index` 允许重复（data-model §3.3 明确写了手动新增可以指定已存在的序号），只按它排序时同号分块的相对顺序由数据库自行决定、每次查询都可能不同，翻页就会出现某条重复出现或整条漏掉。加上主键才构成全序。
- **"内容有没有变"由前端自己判断，后端不多回字段**。判据与后端逐字符一致（两边都不做 trim），后端已经按 api.md 约定"内容一致就直接返回"，再加一个响应字段等于把同一件事表达两遍。
- **`DocumentChunk` 记录里没有 `kbId`**。表里有这个冗余列，但 api.md §4 的响应体没有。写向量时确实需要它——而那条路径本来就要先加载父文档做 `RUNNING` 校验，从文档上取即可。
- **`sha256` 从 `TextChunker` 抽成了 `ContentHash` 工具类**。自动分块与手工编辑写进 `content_hash` 的值必须由同一段代码算出：两边算法一旦不一致，定时同步（工单 17）的内容比对就会把没变的内容判成变了，而症状要到那时才显现。
- **编辑/删除在文档 `RUNNING` 时返回 409**（ui-spec §3 要求，工单原清单没列）。重新处理会整批替换旧分块，此刻的编辑改了也留不住。`message` 与前端禁用按钮的 tooltip 逐字相同。
- **新增 `502 EMBEDDING_FAILED` 的异常映射**。api.md §1 标注它"同步接口路径上才会出现"——入库是异步的，失败写进任务记录；**编辑分块是第一条同步调用 Embedding 的路径**，这个错误码到本工单才第一次可达。不映射的话供应商故障返回 500，前端只能显示"操作失败"。

### 浏览器实测

本机这次**没有注入 `EMBEDDING_API_KEY`**，走真实入库链路会在 EMBED 步失败、切不出分块，所以用 SQL 造了一份"已成功处理过"的文档（24 个分块、其中 #3 禁用且无向量）来验证界面。后端行为本身由 11 条真实 Postgres 集成测试覆盖，这份种子数据只用于验证渲染。

| 验证项 | 实测结果 |
|---|---|
| 列表顺序与分页 | `#0…#19` / 第 2 页 `#20…#23`，`共 24 个`，末页「下一页」禁用 |
| 筛选「仅已禁用」 | 只剩 `#3`，`共 1 个`，分页器消失 |
| 编辑禁用分块 | 内容更新，`char_count` 87→39、`token_count` 87→33 均服务端重算，**向量仍为 0 行**（CHK-22 在界面路径上复现） |
| 三种保存提示 | 逐字命中：改了+启用「已保存，向量已更新。」/ 没改「内容未变化，未重新计算向量。」/ 改了+禁用「已保存。该分块已禁用、不参与检索，因此没有计算向量。」 |
| 编辑启用分块（无 Key） | `502 EMBEDDING_FAILED` → 弹层内提示「向量计算服务暂时不可用。」，**弹层不关闭**（关掉用户改的内容就没了），库中内容原封不动 |
| 删除分块 | 标题 `分块（24）`→`分块（23）`，序号出现空缺（#0 消失、从 #1 开始，符合"不重新编号"）；库中 `chunk_count=23`、存活 23、逻辑删除 1、向量 22（= 23 − 1 个禁用的） |
| 文档 `RUNNING` | 横幅「文档正在重新处理，当前分块即将被替换。处理完成后请刷新。」，全部编辑/删除按钮禁用且 tooltip 与后端 409 的 message 逐字一致 |
| 两种空态 | `revision=0` →「文档还没有处理。」+［开始处理］；`revision>0` 且无分块 →「这份文档没有切出任何分块。」+［重新处理］ |

浏览器 console 无任何错误。
