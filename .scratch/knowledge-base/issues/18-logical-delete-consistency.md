# 18 — 逻辑删除一致性专项测试

**What to build:** 一组专门验证"已删除数据在任何查询路径上都不会复活"的测试。

这张工单是例外——它是横向的，不是垂直切片。原因是逻辑删除的正确性依赖一条**靠约定维持**的纪律：`repository` 层每个查询方法都要带 `deleted = false`。一个方法漏写就是一个 bug，而且不容易在开发时发现（只有恰好去查一条被删数据时才暴露）。这类风险只能用穷举式的专项测试覆盖，分散到各功能工单里必然会漏。

**Blocked by:** 12（文档管理）、15（分块批量启禁用）——需要全部查询方法都已实现

**Status:** done `2026-07-26`

- [x] 每个查询方法都有对应用例：造一条已逻辑删除的数据，确认该方法查不到它
