## 2. Objective

把 Phase 2 已交付的 Chat、流式 Chat、Embedding 与 Rerank 能力端口编排成可用、可停止、可排队、
可诊断的知识问答链路，并为用户提供问答对话页和意图树管理页。

Phase 3 不以一次性“大爆炸”交付为目标，而是形成三个可独立演示和验收的增量：

1. **3A — 记忆 + 改写 + 意图（第 2~9 篇）**：持久化对话历史，压缩长期记忆，改写问题并拆分子问题，
   用可运营的意图树完成匹配、歧义引导和检索动作映射。
2. **3B — 检索 + 工具（第 10~13 篇）**：按意图并行检索知识库、后处理和精排证据，并通过原生
   Function Calling 调用受控 MCP 工具。
3. **3C — 生成 + 流式 + 任务管控 + 排队限流（第 14~18 篇）**：安全组装 Prompt，流式生成答案，
   支持停止、断连处理、排队、公平并发许可、等待超时和唯一终态。

最终至少能演示：

> 用户在对话页发问 → 系统加载并按水位线压缩历史 → 改写问题并匹配可维护的意图树 → 对一个或多个
> xrag 知识库执行有界并行检索，必要时调用白名单工具 → 对证据后处理与精排 → 隔离不可信输入并组装
> Prompt → 通过 `com.app.ai` 流式生成 → 前端呈现排队、生成、停止、完成或失败的唯一终态；诊断记录能
> 解释链路走到了哪一步，而不会泄露用户问题、文档正文、工具结果或模型答案。

## 3. Scope

### 3.1 In Scope

#### 3A — 记忆、改写与意图

- 对话、消息、摘要和任务标识的统一领域模型；对话历史持久化到 PostgreSQL。
- 摘要压缩、水位线与近期原始轮次的组合；摘要失败时的显式产品语义。
- 查询改写、指代消解和有界子问题拆分；失败时是否退回原问题由 3A Step B/C 冻结。
- 意图树的存储、树形增删改、`description` 编辑、节点启停与父子一致性校验。
- 叶子节点绑定 xrag 知识库 ID；不引入 Milvus Collection 语义。
- 意图评分、JSON 容错、并行调度与全局数量封顶。
- 歧义检测、引导式问答和意图到检索动作的映射。
- 意图树方案单独形成 ADR，并在 3A Step C 随技术方案确认。

#### 3B — 检索与工具

- 基于 3A 检索动作的多知识库、有界并行检索与结果归并。
- 检索通道构成、粗排、去重、截断、后处理和精排策略；具体选型留在 3B Step C。
- 调用 `RerankClient` 并显式区分 `rerankApplied=true`、Noop 降级和配置故障。
- MCP 工具采用原生 Function Calling；复用 Phase 2 的 `ToolDefinition`、`ToolCall`、
  `ToolResultMessage` 和流式 tool-call 增量。
- 工具白名单、JSON Schema 参数复核、只读与有副作用工具的产品边界，以及工具失败的显式反馈。

#### 3C — 生成、流式与任务管控

- 场景化 Prompt 组装、上下文预算与模型窗口约束。
- 对用户问题、检索 chunk、MCP 返回和运营 `promptSnippet` 四类不可信内容进行分类隔离；
  3C Step C 必须单开安全章节。
- 通过 `RoutingChatClient` / `RoutingStreamingChatClient` 生成；不得绕过 `com.app.ai` 直接调用供应商。
- 独立的问答 SSE 事件协议，不把 `ChatStreamEvent` 原样投影给前端，也不暴露内部 `ExecutionInfo`。
- Servlet 推送层显式切离 Reactor Netty event loop。
- 停止生成、任务归属校验、部分回复保存、断连策略、取消传播与唯一终态。
- 单实例下的进程内公平并发许可、排队、唤醒、等待超时与拒绝；产品语义保留，分布式机制不照搬。
- 等待预算、模型 Deadline 和 SSE 超时从同一处派生或在启动时校验，避免互相矛盾。

### 3.2 Step B 双界面硬闸门

Phase 3 明确有两个界面，不能合并成一份模糊规格，也不能只为其中一个做原型：

| 界面 | 界面规格 | 可点击原型 |
|---|---|---|
| 问答对话页 | `tech/qa-pipeline/conversation/ui-spec.md` | `prototype/qa-pipeline/conversation/index.html` |
| 意图树管理页 | `tech/qa-pipeline/intent-tree/ui-spec.md` | `prototype/qa-pipeline/intent-tree/index.html` |

- 3A Step B 先产出并确认两套规格与原型的 3A 基线；**两套都经项目所有者确认之前，不得写任何
  Phase 3 前端业务代码。**
- 3B/3C Step B 若增加检索来源、工具调用、排队、流式、停止或失败状态，必须更新受影响的规格与原型，
  并在该段前端实现前再次确认。
- 原型只验证信息架构、状态组合和交互，不直接复制为生产前端实现。

### 3.3 Out Of Scope

- 深度思考（thinking）输入与思考过程渲染；D-07 已明确本期不做。
- 新增第二家 Chat 供应商；本期使用百炼 `qwen-plus`，服务等级是否单档由 Step C 冻结。
- RAG 检索/生成质量评测与模型横向对比；归 Phase 4。
- 多实例部署下的分布式信号量、Redis 队列、Pub/Sub 取消广播、防惊群和租约续期。
- 多租户、复杂权限体系、计费、配额售卖与生产上线。
- 百炼 compatible-mode Prompt Caching 与 Lost in the Middle 结论；两项未经本次一手复核，
  不得作为 Phase 3 设计依据。
- Prompt 热更新、通用工作流编排器或未被 3A~3C 真实路径使用的扩展点。

## 5. Plan

### 5.1 闸门运行规则

三个子里程碑都遵守主计划 §6.1。Step A 只有一份共同基线；“每段走 A~G”是指每段进入时检查
并引用这份已关闭基线，而不是复制、改写或重新确认 Step A。

为避免把每张工单、每个技术节点都变成人工停顿，Phase 3 采用**按 Step 批量授权**：进入一个 Step
时先把该 Step 的产品或技术取舍合成一组，项目所有者一次确认；确认后 AI 可连续完成该 Step 内的文档、
工单、实现和自动验证，不再逐节点询问。只有范围或安全边界升级、不可逆数据操作、新外部依赖、现有证据
推翻已确认裁决、或并行会话发生文件所有权冲突时，才提前停下。

批量授权不取消主计划 §6.1 的产出物硬闸门：B/C/D/E/G 的实际产物仍各需一次确认，且不能用“默认同意”
代替尚未产生的验收证据。一次确认可以同时覆盖该 Step 的全部决策和产物，但不能跨过尚未完成的 Step。

| Step | 每段必须满足的产出/证据 | 进入下一 Step 的条件 |
|---|---|---|
| A | 引用已确认的学习稿、检查点和一手复核 | 共用基线已于 2026-08-07 关闭，不重开 |
| B | PRD 对应增量；受影响界面规格与可点击原型 | PRD 经用户确认；所有受影响原型在写前端代码前经用户确认 |
| C | 技术方案三件套对应章节、ADR、测试矩阵、分角色任务书、原子工单 | 技术方案和技术性取舍经用户确认；工单依赖与测试矩阵一致 |
| D | 该段前后端垂直切片 | API/浏览器演示经用户确认，且不得依赖下一段未实现能力伪造完成 |
| E | 自动化与手工执行结果回写测试矩阵 | 所有结果如实标记 passed/failed/blocked，并经用户确认 |
| F | CI/CD 变更与部署配置登记 | 本段新增门禁本地通过；收费 API 仍由显式环境变量守门 |
| G | 该段复盘与里程碑状态 | 阶段对齐检查点经用户确认后，才开始下一子里程碑的 Step B |

Phase 3 使用一套逐段扩展的主文档，避免三份文档复制后漂移：

- PRD：`docs/prd/2026-08-07-qa-pipeline-prd.md`，按 3A/3B/3C 标记范围和确认时间。
- 技术方案：`tech/qa-pipeline/{architecture,data-model,api}.md`，每段只批准自己的章节。
- 测试矩阵：`tech/qa-pipeline/test-matrix.md`，用 `3A-*` / `3B-*` / `3C-*` 编号分区。
- 分角色任务书：每段一份 `docs/exec-plans/active/YYYY-MM-DD-qa-pipeline-3x-implementation-lanes.md`。
- 原子工单：每段落入 `.scratch/qa-pipeline/3x/issues/`，不能把下一段工单混入当前完成口径。
- Step G：每段各有 `docs/retro/YYYY-MM-DD-phase-3x-*.md` 与
  `docs/status/YYYY-MM-DD-phase-3x-*.md`；3C 的状态文档同时给出 Phase 3 总关闭结论。

  全系统逻辑删除约束，向量等派生索引按既有例外处理。
